## 1. 目标与实施顺序

提供可操作的本地 Web 界面，让使用者提交任务、观察执行过程、查看成果，并用于项目演示和故障排查。基础控制台采用 React、TypeScript、Vite 和 Ant Design，复用现有 Runner。

每次迭代先明确后端接口、事件与状态契约，在同一迭代内交付后端能力和对应页面，再完成联动验收。独立验收、上下文第一阶段与多轮任务交互已有操作和展示；分层历史压缩由宿主 TOML 配置，页面展示证据；中断后沿用普通输入框接续，每条消息对应独立运行。

启动、宿主配置与 HTTP/SSE 字段见 [控制台说明](WEB_CONSOLE.md)。本文维护页面行为和验收要求，不重复维护操作说明或每次测试数量。

## 2. 首版页面与功能

| 页面 | 必须提供的内容 |
| --- | --- |
| 新任务与历史 | 首页中央提供项目文件夹选择、任务输入和发送，展示最近项目及最近任务；高级项折叠；完整历史支持刷新、分页、状态筛选和进入详情 |
| 任务详情 | 展示当前执行阶段与耗时、模型和工具调用次数、剩余额度、按顺序排列的事件、工具参数与结果、错误与结束原因；可取消运行中的任务；展示最终回答、产物列表及验收结果 |
| 运行配置 | 编辑模型、五类工具、模型轮次、工具次数和总时限；校验并应用本次运行的覆盖值；密钥来源只显示环境变量名称，不接收或回显密钥值 |

产物可预览或下载；长输出预览必须保留截断提示，并能打开已保存的原始记录。产物访问仅限该运行登记的产物和允许查看的记录，不能凭任意宿主路径下载文件。

任务列表的历史查看和页面刷新不触发工具重放，也不等于恢复执行。V0.2 已在详情页提供任务结束后的追加要求和连续对话，详见第 10 节；每条被接纳的要求对应独立运行。基础配置页提供查看及本次覆盖，手动技能沿用现有选择与快照。真实任务验收和首版候选比较复用任务详情、差异、产物与测试记录；命名任务预设、策略管理及独立优化页面按实际需要另行规划，不作为 V0.2 或 V0.3 首版的前置要求。

## 3. 状态与运行体验

- 复用后端的运行状态、事件、预算和验收契约。执行、验收与清理状态分别显示；只有 completed、passed 且清理为 not_needed 或 complete 时，才展示任务成功。未验证、验收异常或清理未知/不完整时不得展示为成功。
- 真实显示“等待模型响应、正在执行工具、正在验收”等阶段与已耗时，避免请求等待期间界面没有反馈；不得伪造百分比或事件。
- 模型调用次数与 HTTP 重试次数分开展示；缺失用量保持未知或不完整，不展示为精确零用量。
- 取消按钮只提交取消请求。后端确认结束前显示“正在取消”；最终保留用户中断、上游取消、内部异常、超时和清理结果等真实原因。重复点击或重试取消请求不能产生重复终态。
- 首批沿用单任务运行限制；已有任务运行时明确显示忙碌并拒绝新提交，不能让界面看似接受了实际未启动的任务。
- 提交、查询和订阅失败时给出可读错误，并保留表单输入；空历史、加载中与连接中断有对应提示。

## 4. 后端协作要求

前端通过任务 API 提交、查询和取消任务，通过 SSE 订阅执行事件。后端复用现有 Runner，不在网页服务里另写一套模型与工具循环。

后台任务生命周期独立于单个 HTTP 请求和浏览器连接。关闭页面、刷新或订阅断开都不能自动取消运行；后端服务重启后可读取既有轨迹；可信中断记录可通过普通消息接续，刷新本身不会执行。

事件使用现有 run_id 和连续 seq；断线重连按已收到的序号补齐记录并去重，最终状态以持久化记录为准。前端可以根据后端时间计算等待时长，但不能由等待时长推断任务已经超时或成功。

模型密钥由后端环境变量读取，不进入前端包、接口响应或浏览器存储。网页填写的目录和配置由后端继续校验；浏览器无法选择的宿主目录不得假装成有效工作区。

### 4.1 同步变更与契约维护

每次修改后端代码，都检查前端影响；以下变化必须在同一迭代内完成对应前端更新：

| 后端变化 | 必须同步的前端内容 |
| --- | --- |
| 请求、响应或配置字段 | 接口调用、类型、表单、默认值、校验和错误提示 |
| 工具集合、参数或结果 | 配置中的可用工具、参数与结果展示、输出截断提示及产物链接 |
| 运行、验收或清理状态及结束原因 | 状态标签、阶段提示、操作可用性、成功判断及异常说明 |
| 事件类型、载荷或序号规则 | 事件解析、时间线、重连去重与最终记录核对 |
| 产物索引或访问规则 | 列表、预览、下载与失败反馈 |

每个受影响功能都同步更新相关测试和需求、接口或使用文档。版本或功能迭代的 Plan 列出上述映射及验收场景；确实不影响前端的内部后端变更，交付时说明原因。接口字段说明包含业务含义、单位、默认值、可选性和状态约束，前端不自行推断未知值。

### 4.2 独立验收的页面映射

下表已在前端共享类型、时间线与验收面板接入；完整定义见 [技术设计第9节](TECH_DESIGN_V0.1.md#9-独立验收协议与状态收尾)。

| 后端字段/事件 | 对应前端行为 |
| --- | --- |
| verification=null | 展示未运行验收或旧记录无详情；结合validation_status与跳过原因展示，不推断失败 |
| verification.status与顶层validation_status | passed/failed/error分别显示验收通过、产物未通过、验收异常，保持两者一致 |
| verification.reason / exit_code | 展示受控原因和验收子进程退出码；None表示没有拿到进程退出码 |
| verification.elapsed_ms / stdout / stderr / truncated | 毫秒耗时、有界双流预览与截断提示；stderr非空不能自行推断验收失败 |
| verification.artifacts | 展示验收原始双流引用，经受限产物接口打开；沿用location/path/kind |
| verification.timed_out / cancelled / output_limit_exceeded / cleanup_status | 明确显示超时、取消、输出超限和清理结论，保留模型已经完成的执行状态 |
| execution_completed | 阶段切换为执行已完成，等待验收或最终收尾；不能提前展示整项成功 |
| verification_started | 显示正在验收与自身秒级预算；连接中断不取消后台运行 |
| verification_result | 展示宿主详情；模型回答保留原文，其内容不能覆盖验收字段 |
| verification_skipped | reason=not_configured或execution_not_completed；明确展示未验收原因 |
| run_finished | 按持久化最终结果确认结束；总超时/取消发生于验收时，执行仍completed、验收为error |

验收器采用后端维护的预设，前端提交预设标识，不接受模型或网页传入任意宿主 argv。当前通过/api/options读取宿主登记项，提交workspace_id/verifier_id；实际接口及单位约定见 [控制台说明](WEB_CONSOLE.md#5-http契约)。

## 5. 首批验收标准

| 编号 | 场景 | 可观察的通过条件 |
| --- | --- | --- |
| F01 | 网页提交正常任务 | 从页面打开真实文件夹并提交任务，获得运行标识并进入详情；产生与 CLI 同契约的记录、成果和真实验收状态；已配项目测试实际执行，无验收任务明确保持unverified |
| F02 | 实时执行与等待 | 执行中可看到当前阶段、已耗时、模型/HTTP/工具计数和顺序事件；工具输出与真实记录一致 |
| F03 | 状态与产物 | 独立展示执行和验收状态；能查看回答、预览或下载登记产物；没有验收入口时不展示为成功 |
| F04 | 历史与重连 | 刷新、关闭再打开页面或短暂断网后，仍可查询任务；重新订阅补齐事件且不重复工具动作；断开连接不取消任务 |
| F05 | 主动取消与异常 | 网页取消经后端确认后结束；超时、工具错误和内部异常有真实原因及清理结果，保留取消前已保存输出 |
| F06 | 无效配置与忙碌 | 无效路径或参数在启动前给出错误；运行槽位被占用时明确拒绝新任务，不生成假运行状态 |
| F07 | 凭据与访问边界 | 页面与接口无模型密钥；配置只接收支持字段；不能通过产物请求读取任意宿主文件 |
| F08 | 前后端同步回归 | 每项影响前端的后端变更均有对应调用、类型、页面或交互更新；通过受影响的契约检查与页面联动场景，核对实际请求、事件和最终展示，相关文档同步更新 |

每个切片按实际变更选择上述场景，并保留联动验收结果；基础控制台整体交付时覆盖 F01—F08。仅接口可调用或后端测试通过，不算对应前端功能验收完成。

## 7. 验证记录与已知限制

已有测试结果、真实模型记录和 F01—F08 证据映射集中维护在 [控制台验证记录](WEB_CONSOLE.md#7-已保留的验证证据)。新增迭代在完成实际检查后追加日期与结果，不将历史结果当成新验收。

普通目录和 Git 隔离的历史产物均从对应轮的固定快照读取，后续覆盖同名文件不会改变旧轮下载；证据缺失或损坏时明确报错。工作区来自本机系统选择或宿主初始登记；选择由服务端原生窗口完成，网页不提供任意宿主路径提交或文件下载接口，自动续跑也未实现。当前阶段与后续路线见 [项目概览](../PROJECT.md)。


## 8. 真实项目任务与审阅

首页直接打开项目文件夹并识别 Git 或普通目录，不要求用户先在配置中登记。Git 项目显示分支、提交、未提交状态和可选测试；提交项目编号和 execution_mode，只有明确选择 Git 隔离才附带基线；不夹带普通工作区或验收器编号。默认使用所选目录当前文件，包含未提交改动；Git 隔离从选定提交创建工作树。不可用项目显示明确原因，无提交仓库不可发送；未配测试时保持未验收。

详情检查器的“代码”页签：列出变更文件、基线、独立目录与纯文本 diff，显示二进制/预览截断标记并提供完整补丁下载。保留、丢弃及其失败反馈保持在当前任务；丢弃需要明确确认。运行中、快照未就绪或错误时禁用不适用操作，不能将测试通过显示为已接受代码。保留后不暗示已合并原分支，丢弃后继续显示历史测试与保存补丁。

联动验收覆盖项目表单、正确/错误修改的真实测试、取消后的改动、刷新与服务重启后待审阅结果，以及保留/丢弃操作与原目录保持一致。API与业务边界见 [代码任务与审阅](PROJECT_TASKS.md)，证据集中于 [控制台说明](WEB_CONSOLE.md#7-已保留的验证证据)。


## 9. 上下文管理第一阶段

根 AGENTS.md 加载开关、整体输入、指令文件上限和压缩参数由宿主 TOML 配置；普通设置页只公开模型、工具和三项任务预算，不发送 context 覆盖值。修改公开预算不得覆盖宿主内部策略。

详情检查器的“上下文”展示实际来源状态、固定指令全文与摘要、最新拟请求轮次、输入大小、预算和占比。输入计量明确为消息及工具定义的 UTF-8 JSON 字节，不表示 token。超限展示实际大小与原因，不能用达到轮次上限的文案替代。指令错误展示具体问题；尚无检查和旧记录分别显示未知，不填零。普通文本渲染项目指令，不执行其中的 HTML。

前后端联动需验证三项预算应用后的实际提交及内部策略保持、首轮零请求超限、工具执行后超限保留文件、正常加载与历史刷新/重启。最新统计使用 RunView.context，不依赖有显示上限的事件列表。完整契约见 [上下文管理](CONTEXT_MANAGEMENT.md)，验证结果集中于 WEB_CONSOLE.md。


## 10. 多轮任务交互（V0.2）

本节首版已交付。产品语义及 M01—M06 验收以 [PRD 4.3](PRD.md#43-多轮任务交互的交付范围v02) 为准。沿用现有工作台与详情页，详情为持续会话工作区：中间展示消息，底部固定输入栏，右侧按轮查看详情，手机使用抽屉。各轮要求、回答和过程来自后端真实会话/事件，实际执行仍由 Runner 完成。

| 页面能力 | 必须满足的行为 |
| --- | --- |
| 追加要求 | 详情页提供输入与提交；上一轮结束且条件可核对后可发起新运行，提交失败保留输入；运行中提示等待或取消 |
| 连续对话 | 按顺序展示用户要求与 Agent 回答，明确每条要求对应哪次运行；工具轨迹仍可进入对应运行查看 |
| 历史与代码继承 | 后续运行继承必要历史及此前代码修改，界面能查看所属会话、前序运行和代码来源 |
| 逐轮证据 | 展示各轮独立预算、执行状态、测试结果和代码差异；允许回看旧运行，旧测试与补丁不被新轮次覆盖 |
| 测试与审阅 | 新一轮修改重新测试、重新待审阅；最新结果与历史通过/保留决定分别显示 |
| 错误与边界 | 忙碌、重复提交、代码已丢弃、状态无法核对和输入超限时显示后端原因，不暗示已经继续执行 |
| 刷新与重启 | 恢复读取会话与运行关系；再次提交前核对工作区；读取和重新订阅不会自动发送用户消息或执行工具 |

未确认的请求在当前标签页保存固定请求编号、正文和公开配置；网络失败后重试沿用原载荷，刷新仅恢复草稿、不自动提交。审阅/快照恢复后同步刷新会话的可继续条件；检查旧轮只切换详情，发送始终追加到会话最新轮；运行中允许编辑但禁用新提交。未知发送结果提供“重试确认”，沿用原父轮与载荷核对请求，不受当前草稿变化影响。完整接口、错误与快照限制见 [多轮任务交互](MULTITURN_TASKS.md)。

联动验收从“首次修改完成 → 页面追加要求 → 新运行继承历史和代码 → 再次测试与差异 → 审阅”开始，核对实际请求、事件、产物和持久化结果。另覆盖刷新/服务重启、运行中提交、重复请求、无效工作区及输入预算不足；不得以单纯展示对话记录代替执行链路。


### 10.1 会话工作区体验

消息区采用用户靠右、Agent靠左的连续排版，顶部只保留会话标题、项目、最新状态及停止/详情入口。消息正文不单独限高滚动；代码块和表格可横向滚动。最终回答以受限Markdown显示标题、列表、表格和代码复制，用户输入、工具参数、输出和补丁仍按纯文本转义，禁用原始HTML及危险协议，外部图片只显示替代文本。

输入栏始终位于会话视口底部；Enter发送，Shift+Enter换行，中文输入法确认文字不发送。发送前显示明确待确认状态，收到POST真实运行才补入会话；新轮不重建消息区域或输入节点。发送期间编辑的新草稿保留，普通未发送草稿与未知请求都按会话保存到当前标签页；刷新不自动执行。

最新轮复用唯一SSE显示执行过程，历史过程按展开动作读取最多100条事件，更多记录在检查器完整轨迹中查看。等待、工具结果、验收与错误由真实事件/快照确定，缺少结果保持未知，不生成伪流式回答。用户位于消息底部才自动跟随；上翻阅读历史时显示“回到最新”。

查看本轮详情只切换运行检查器，预算、测试、代码、产物和审阅均属于该轮；输入始终继续会话最新代码。旧run链接及tab=context/code/trace/artifacts仍可定位详情。桌面可收起侧栏，窄屏用抽屉，关闭详情不清空草稿或改变消息位置。验收覆盖至少三轮连续操作、历史选择、复制、输入法、停止、失败/重试、刷新及390像素布局。

## 11. 分层历史压缩

宿主 TOML 支持 off/masking/hybrid、触发与目标比例、外置阈值、近期批次、摘要调用/正文上限及可选模型窗口；普通设置页不提供这些控件。说明摘要占模型轮次和用量，read_context自动只读启用且计工具次数。详情展示原始/实际输入、本地token估算及其不确定性、真实变换范围、前后大小、引用和结构化摘要；继承摘要明确显示未额外调用模型。失败和未记录分别呈现，摘要不能冒充本轮测试通过。页面验收覆盖提交、压缩、续聊、回读、无效摘要、取消与刷新；原始对话和轨迹可查。

## 12. 中断后普通消息接续（2026-10-23）

中断状态沿用原会话消息与输入框。允许继续时展示continuation_notice，用户直接发送“继续”；没有独立恢复按钮。旧轮保持中断，新轮正常记录用户消息、执行、测试和审阅。刷新、重连和读取提示均不POST；未知发送沿用原request_id确认，输入节点与草稿保留。


## 13. 手动技能选择与逐轮快照

新任务表单展示宿主发现的技能名称、用途及不可用原因，最多手动选择八项。后续消息输入区默认沿用最新运行的技能选择，可更换或全部取消；旧首轮配置草稿不能覆盖续轮继承。发送结果未知时，重试保持原请求及其选择不变。

上下文详情展示该运行事件中的完整技能快照：名称、用途、来源、指纹、字节数和折叠原文，普通文本渲染；无选择与加载失败分别展示。不能用当前目录内容补造历史快照。页面验收覆盖实际请求、模型输入、真实文件和项目测试、续轮清空及刷新；协议见 [任务技能](SKILLS.md)。


## 14. 打开本机项目与新任务首页

默认 /runs 展示新任务工作区：简短标题、中央任务输入、当前项目与真实路径、发送按钮、最近项目和最近会话。全部会话通过 /runs?view=history 进入，按会话分页和最新状态筛选；项目页为 /projects/{id}，详情页和持续会话保持原交互。

| 操作 | 页面与后端同步行为 |
| --- | --- |
| 选择项目文件夹 | 明确点击后 POST /api/projects/pick，等待 Windows 系统窗口；等待期间保留输入并防止重复选择，取消恢复原状态 |
| 打开最近项目 | POST /api/projects/{id}/open 重新核验目录并更新最近时间；显示真实返回的类型、路径和 Git 信息，不仅切换本地标签 |
| 不可用项目 | 显示来源原因并禁用发送；移动/删除、子目录、裸仓库或没有提交不得伪装成普通可执行目录 |
| 高级设置 | 默认原目录，可明确选择隔离；基线只在Git隔离时显示；保留技能、模型/预算、项目测试和产物配置 |
| 保存项目测试 | 仅在 Git 项目显示命令和秒级超时，显式保存后提示已保存；留空可清空，保存不执行命令，也不显示为测试通过 |
| 失败与忙碌 | 选择、登记、保存及发送失败分别反馈，保留任务文本；已有运行仍受单槽限制 |
| 小屏布局 | 目录长路径可换行或截断并可查看完整值，输入、项目与发送操作不横向溢出；高级项和最近列表可访问 |

最近项目由后端持久保存；本地浏览器仅记住选中编号，不保存模型密钥或把浏览器文件句柄当成服务端路径。原生选择器不可用时展示同机 Windows 条件与后端返回原因；不静默切换为上传文件或填写任意路径。完整协议和限额见 [打开本机项目](LOCAL_PROJECTS.md)，联动验收采用 PRD P01—P06，并在 WEB_CONSOLE.md 记录实际结果。


## 15. 项目下的会话入口

桌面侧栏常驻新建对话、全部会话、项目树和运行配置。项目名称可进入该项目会话页，展开后展示最近会话，条目使用稳定session_id；同一会话追加轮次只更新入口、轮数与最新状态。当前会话在所属项目下高亮，更多条目由项目页分页展示。手机通过导航抽屉访问同一结构。

项目页明确区分“新建对话”与点击已有会话继续。新建入口固定当前项目，不误用上次选择；新建文字草稿按项目隔离，已有会话草稿沿用会话编号保存。首页、项目页和全部会话使用相同后端聚合摘要，不能把每轮运行当成独立对话，也不能只对已分页运行去重。加载、空列表、刷新失败、未关联项目和记录异常均明确展示，历史浏览不发起执行。

验收对应PRD N01—N04，接口和来源身份规则见 MULTITURN_TASKS.md 第11节。


## 16. 原目录执行与可见路径

打开本机文件夹后默认发送 execution_mode=local，会话头部显示“原目录执行”和完整实际路径（长路径可省略并通过title查看）。高级设置可选择isolated；执行位置不从文字草稿恢复，切换项目目录回到local；只有Git项目能明确选择创建独立工作树，普通个人目录不提供隔离入口；保存测试设置不改变本次选择。Git提交基线只用于isolated。既有会话模式不可在续轮切换。

原目录代码页展示“修改已在原目录生效”、本轮开始至结束的文件变化与固定文本差异，不出现保留/丢弃工作树。采集超限、失败和损坏不得伪装成无变化或测试失败，仍允许在可信原目录继续。原目录Git仍使用项目测试文案；详情展示所选项目、执行方式和实际执行目录。旧轮产物使用该轮快照，缺失时明确告知而非显示新内容。验收对应PRD D01—D05。

## 当轮 Python 执行信息（2026-10-27）

运行详情“概况”同步显示默认Python解释器和源码导入目录，取自RunView.python_execution的该轮快照。查看旧轮使用旧值，新运行或当前宿主配置不能替代；未准备的快照为null时不推断环境。源码目录配置由宿主管理，本轮不新增任意路径或环境变量编辑入口。具体契约见 [Python源码导入](PYTHON_EXECUTION.md)。

## 项目执行配置与共享目录（2026-10-27）

高级设置支持 Python 解释器输入和明确保存，普通目录也可用。RunView.project_workspace 提供会话目录当前状态；历史检查器始终只读，即使缓存仍记录该轮曾为最新，也不显示保留/丢弃按钮。最新轮确认操作针对整个会话工作树。丢弃后保留历史产物入口，由 API 读取固定快照，缺失时不返回当前文件。验收对应 PRD X01—X06。
