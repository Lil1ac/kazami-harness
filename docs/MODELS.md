# 模型服务

桌面进入「运行配置 → 模型服务 → 添加服务商」。填写名称、Base URL、认证方式和默认模型 ID。远程连接填写 API Key，本机回环服务可选择免密。点「添加模型」可登记更多模型 ID，共用这条连接和密钥。保存后可以在列表测试连接。测试使用固定合成消息，检查流式正文及工具调用格式，不读取项目或会话。

新建对话从已登记的模型中选择。首次登记启用的服务商后，宿主自动选用该连接的默认模型。运行配置的「任务默认项」可更改默认模型，「角色模型」可为探索和审阅另选模型。角色留空时继承当前会话模型，开发角色始终继承当前会话。

## 独立 Web 与 CLI

在运行 TOML 中登记服务商，标识以 custom- 开头。模型 ID 按服务商实际要求填写。远程认证在 api_key_env 填写宿主环境变量名，密钥值只设置在启动终端。本机免密连接使用 auth = "none" 并省略 api_key_env。

~~~toml
provider = "custom-gateway"
requested_model = "your-model-id"

[custom_providers.custom-gateway]
name = "我的网关"
base_url = "https://example.com/v1"
default_model = "your-model-id"
models = ["your-other-model-id"]
api_key_env = "HARNESS_MODEL_KEY"

[role_models.review]
provider = "custom-gateway"
requested_model = "your-other-model-id"
~~~

省略 provider 时使用首个启用的服务商，省略 requested_model 时使用该服务商的默认模型。CLI 可以用 --provider 和 --model 切换到目录中的其他组合。桌面应用通过系统加密存储读取密钥，使用独立 Web 和 CLI 的配置文件时仍需在桌面保存对应凭据。

## 接口与凭据

在 Base URL 填写接口根路径。程序追加 /chat/completions，要求 OpenAI Chat Completions 风格的 SSE 文本和工具调用。服务返回用量时会写入运行记录，未提供的用量显示为未知。远程地址使用 HTTPS，HTTP 和免密仅限本机回环。请求固定到登记地址，禁用环境代理及重定向。

编辑时留空 API Key 会保留同一连接的凭据。修改地址或认证方式后使用新的凭据分区，需要为新地址输入密钥。旧会话、已排队任务和自动化保留原端点绑定，变更后按原绑定检查并给出重新提交或审核提示。运行历史显示当时选择的服务名称、请求模型和实际响应模型。

从含固定内置项的开发版本升级时，需重新登记原来使用的服务商。如果旧桌面设置保存了内置模型，先备份 `settings.json`，在 `config` 中将 `provider` 和 `requested_model` 改为 `null`，将 `role_models` 改为 `{}`，再启动并配置模型。新版本采用当前配置与运行清单格式。
