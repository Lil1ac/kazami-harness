## 调研依据与适用范围

Anthropic 于 2026-11-06 发布的 [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory) 将跨会话记忆分为可搜索轨迹、记忆笔记、派生知识表示及预加载上下文，并讨论 dreaming 对这些材料的整理。它明确区分跨会话记忆和单会话 compaction。对本项目的启发是保留原始证据、将整理产物视为可失效的派生数据，并通过消融实验决定是否采用；不能将上下文压缩的成绩称作长期记忆收益。

[Anthropic Agent evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) 强调区分任务、重复试次、轨迹、最终环境和评分器。本项目以可执行功能检查计分，以轨迹解释失败，不采用模型自述完成作为成功依据。人工检查需求与评分器是否一致仍必不可少。

[LongMemEval](https://github.com/xiaowu0162/LongMemEval) 涵盖提取、多会话、时间、更新和拒答；其仓库已链接 [LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2)。[LoCoMo](https://github.com/snap-research/locomo) 可补充长会话记忆研究。这些不是本地代码任务的直接替代，当前没有运行这些公开基准，不报告它们的分数。

## 执行逻辑

1. 读取题集并冻结所选 split 的起点、参考解、评分脚本、模型配置、随机种子、Python 环境和运行时代码 SHA256，保存 `protocol.json`。不保存密钥。
2. 对每题运行预检：起点必须评分失败、参考解必须通过。坏题或评分环境异常停止整批，不归因于模型。
3. 将题目 × 策略 × 重复次数的计划随机交错，提前分配 Run ID。每次建立新工作副本，关闭记忆读取/写入、技能、MCP 和自动修复，防止前一试次影响后一试次。
4. 复用现有 `run_task`，保留原 Run 的状态和轨迹。执行结束后将产物复制到另一目录，由宿主运行固定评分脚本，不采信 Agent 修改的测试。
5. 每次开始和结束都保存检查点。取消和异常保留已启动试次；硬终止后的 `active_trial` 只表示未结束记录，不证明进程仍存活。读取报告不会恢复或重放模型调用。
6. CLI 打印批次编号，网页侧栏“评测”读取同一 runs 目录中的报告，逐次链接既有运行详情。

运行目录布局：

```text
<runs-root>/<run-id>/                  原有 Run 轨迹和产物
<runs-root>/.evaluations/<batch-id>/
  protocol.json                      固定题集、配置、代码和环境指纹
  report.json                        原子保存的计划、预检、试次与统计
  review.json                        可选质量复核，绑定协议指纹，不改原始评分
  preflight/                         起点与参考解评分证据
  grades/                            逐次外部评分脚本和进程证据
<work-root>/<batch-id>/               独立起点、Agent 工作区、评分副本
```

`local`后端适用于可信本机夹具，单副本最多8MiB UTF-8文件，独立目录不提供操作系统隔离。`swebench`后端使用下述Docker路径，支持真实仓库和二进制文件；不自动恢复付费试次或清理历史证据。二者共用Runner、预算、统计和只读报告。

## 真实仓库六题试点

本轮批准范围为3个仓库、6题、off/hybrid各1次，共12次。官方[SWE-bench评分流程](https://www.swebench.com/SWE-bench/guides/evaluation/)将补丁应用到仓库并运行测试；本项目复用`swebench==4.1.0`规格生成器、测试解析器和官方Docker镜像，由现有Harness负责Agent执行和预算。Windows不能直接导入上游依赖Unix `resource`的编排入口，因此用独立解释器桥接规格和评分模块，**没有声称运行官方CLI原样流程**。

题目来自[Verified数据集](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified)，完整记录在题集目录，内容纳入协议SHA256。六题是预先查看修复规模后选择的较小开发任务，并经过环境筛选，属于便利样本，不是随机抽样。原始issue有时含修复提示，原文保留；不向模型提供`hints_text`、参考补丁和新增测试补丁。它们已是公开数据，不能排除模型训练污染。

| 仓库 | 候选任务 | 验证目标 |
| --- | --- | --- |
| pytest | 5262、7521 | 输出流接口、换行保持 |
| Django | 16082、17029 | 表达式类型推断、应用缓存清理 |
| SymPy | 22914、23950 | 代码打印、集合表达式 |

模型调用前的排除记录：Requests 1921/5414在无网络容器中，参考补丁仍有官方PASS_TO_PASS断言失败；6028仅列为替换候选，未运行。Django 16429的不同测试共享文档描述，官方解析结果把一个失败条目标为成功，未满足本试点的严格基线复现门禁，因此改选16082。保留原预检报告，不修改官方断言列表以凑通过。这些筛选不能隐藏为随机六题结果。

执行路径为冻结 issue、commit、镜像 ID、源码和评分脚本指纹，完成六题零模型预检后开一个付费批次。按固定种子排序，同题两策略相邻且各有三题先执行。每次从干净基线建立独立工作区，Runner 调用 DeepSeek，宿主从固定基线采集补丁，另一全新容器应用补丁与官方测试并记录两类判定。

- 每个命令容器只挂载本试次源码，`--network=none`，2 CPU、2GiB、256 PID、移除Linux capabilities；模型密钥、Docker socket、评分器、其他试次均不挂载。项目依赖来自镜像，不临时联网安装。容器命令间只保留工作区文件。
- 采集补丁时分别传入工作区文件归档与固定 Git 元数据归档，在容器本地解包并比较。Windows 绑定挂载只传输归档，Git 在容器本地读取小文件。工作区中的 `.git` 不参与比较，模型自行提交后，宿主仍能按原始基线提取改动。
- Windows工作区将归档中直接指向内部普通文件的符号链接物化为相同字节；Django涉及4个文档图片别名。目录链接、链式链接和越界链接拒绝。此适配纳入运行代码指纹；评分容器仍保持官方原始仓库结构。
- 评分容器从精确commit开始，应用候选补丁和固定官方测试。原始双流先合并，再以32MiB上限保存并解析，不能拿截断日志评分。每次命令结束或超时均移除唯一容器；清理不能确认则停止批次。
- 零模型预检要求全部 FAIL_TO_PASS 在基线失败、全部 PASS_TO_PASS 在基线通过，参考修复全部通过，并实际完成工作区解包与 Git 初始化。付费批次绑定该预检编号，使用已固定镜像 ID 重新导出基线并核对源码及评分规格。任何差异在付费阶段前阻止执行。
- 文件工具仍由Windows宿主执行；上述隔离适用于这组可信公开任务，不作为任意恶意代码的多租户安全承诺。工作根目录应短且位于D盘，避免Windows路径长度问题。

```powershell
uv --cache-dir .uv-cache venv .runtime/swe-env
uv --cache-dir .uv-cache pip install --python .runtime/swe-env/Scripts/python.exe -r evals/swe-pilot/requirements.txt

# 评分使用 Linux 容器；数据目录保持简短，且与执行目录互不包含。
$pilot = @(
    '--suite', 'evals/swe-pilot/suite.json', '--config', 'evals/swe-pilot/deepseek.toml',
    '--swe-python', '.runtime/swe-env/Scripts/python.exe', '--runs-dir', '.runtime/swe-v2/r',
    '--work-dir', '.runtime/swe-v2/w', '--split', 'dev', '--groups', 'off', 'hybrid', '--repeats', '1',
    '--max-model-calls', '360', '--max-known-tokens', '5000000', '--max-cost-usd', '3.00'
)
.venv/Scripts/harness.exe eval @pilot --preflight

# 使用上一条输出的预检 UUID，凭据通过进程环境提供。
.venv/Scripts/harness.exe eval @pilot --require-preflight <预检UUID>
```

每试次至多 30 次模型调用（含至多 2 次摘要）、80 次工具、600 秒。单条模型请求或容器命令 90 秒，单次模型输出 8192 token，独立评分 600 秒。两策略共享 65,536 字节输入上限，每轮只允许一次 HTTP 尝试。

整批最多 360 次模型调用和 360 次 HTTP 尝试。逐请求在报告检查点保存 $0.35 预留，再经共用模型网关发送执行或摘要。有效回执按峰时价核销。500 万已知 token 是回执后检查的停止线。未返回可信用量时保留预留并停批。$3.00 是冻结费率下的客户端发单上限，按缓存命中输入、未命中输入和输出核算，实扣以供应商账单为准。[DeepSeek 定价](https://api-docs.deepseek.com/quick_start/pricing/)

模型请求和评分证据分别记账。已结算且可评分的普通任务失败仍保留在试次中。评分环境异常、清理未确认、人工取消或预算拒绝会保存批次停止原因及完整计划；已启动未结束与未启动分开显示。在 Web 或 Electron 选择同一运行记录根目录，打开「评测 → 批次 → 同题对照」，可分别核对完整交付和独立评分。展开试次可进入原始 Run，下载候选补丁、官方评分 JSON 和测试日志。

## 指标与统计口径

| 指标 | 定义与缺失处理 |
| --- | --- |
| 任务成功率 | 执行 completed、外部评分 passed 且进程清理确认的次数 / 已结束试次数；未完成全部计划时标为阶段值 |
| pass^3 | 每题前三次全部成功的题目比例；所有题均有三次回执后才展示。它不同于至少一次成功的 pass@3 |
| 每成功任务 token | 本组全部试次的 token（含失败、摘要）/ 成功次数；任一请求用量未知或零成功时为空 |
| p50 / p95 | 启动试次至外部评分结束的墙钟秒数，包含失败；最近秩分位数，当前不拆出纯模型时延 |
| 请求人工输入率 | 进入 waiting_input 的试次比例；本轮不救援，不等于用户实际干预次数 |
| 模型/HTTP/工具次数 | 复用 Runner 汇总；摘要包含在预算中，HTTP 重试与逻辑调用区分 |
| 上下文事实 | 输入字节峰值、摘要次数、是否发生外置/遮蔽/摘要；字节不冒充精确 token |
| 配对差与区间 | 全部计划完成且至少2题时，每题取各重复成功均值的差，再按题重采样 2000 次，给出百分位 95% 区间；单题不展示区间 |

计划试次数、已结束数及未结束记录始终保留。工程错误和超时不会被挑掉以提高成功率。配对区间仅描述这套题，少量题或同源题相关性会限制外推，不能将“区间包含零”解释为证明两策略等价。

真实请求使用官方 DeepSeek 服务；`deepseek-flash` 对应版本和价格参考 [官方模型文档](https://api-docs.deepseek.com/quick_start/pricing/)，运行中另记录 `response_model`。别名未来可能变化，故保留日期与响应；API 不返回唯一权重标识时不承诺模型可永久复现。当前不输出美元费用，避免混淆输入/输出、缓存、峰谷和缺失用量。

## 运行方式

在项目根目录执行；密钥通过 `DEEPSEEK_API_KEY` 环境变量配置，勿写入题集或命令历史。桌面加密凭据不会自动导出给 CLI。

```powershell
# 无模型调用，检查题目是否有效。
.venv/Scripts/python.exe -m agent_harness eval --suite evals/context-v1/suite.json --config evals/context-v1/deepseek.toml --runs-dir .runtime/eval-real/runs --work-dir .runtime/eval-real/work --preflight

# 首批：10题 × 2策略 × 1次；输出独立新批次，不覆盖先前失败。
.venv/Scripts/python.exe -m agent_harness eval --suite evals/context-v1/suite.json --config evals/context-v1/deepseek.toml --runs-dir .runtime/eval-real/runs --work-dir .runtime/eval-real/work --split dev --repeats 1 --max-model-calls 160 --max-known-tokens 2000000

# 使用同一 runs-root 回看报告与原始 Run。
.venv/Scripts/python.exe -m agent_harness serve --config evals/context-v1/deepseek.toml --runs-dir .runtime/eval-real/runs --port 18835
```
