# 本机自动化

本轮C16首版将时间和本机运行事件转换为现有JobQueue请求，执行继续经过Runner、权限、Hooks、预算、资源调度及验收。规则、触发账本、单次运行、通知分别持久保存；页面、桌面和历史共用同一事实源。

## 使用

侧栏“自动化”选择已登记项目，填写任务和触发条件。Git项目默认独立工作树，普通目录直接执行；高级公开配置可保存模型、工具、技能、记忆选择和预算。保存或编辑后均暂停，先预览执行时间并立即试跑，再明确启用。每次触发建立新会话，既有项目记忆按保存策略加载并固定当次版本，不自动继承上次自动化会话。

审核授权页展示实际项目、完整有效配置、固定验收和已登记Hook。命令使用精确`argv`及项目内`cwd`，例如`[{"argv":["python","-m","pytest","-q"],"cwd":"."}]`。不支持自然语言命令、前缀匹配或通配符放权。

规则历史展示原计划时间、跳过/合并原因、作业、执行与验收状态。本机事件规则还提供来源运行入口。事件分析接收有界原任务、回答、终态和公开项目测试输出；这些内容标为来源数据，不授予权限，独立验收输出不回传模型。

## 时间、重叠及恢复

| 项目 | 行为 |
| --- | --- |
| 触发类型 | 一次性带偏移ISO时间、至少一分钟的固定间隔、五段Cron、同项目普通主运行完成/验收失败事件 |
| 时区 | 保存IANA名称，默认`Asia/Shanghai`；Windows发布包含`tzdata`。Cron由APScheduler计算，星期数字0为周一，推荐`mon-fri`等名称 |
| 夏令时 | 不存在的本地时刻跳过，重复本地Cron时刻以同一幂等键合并；间隔按UTC持续分钟计算 |
| 正常触发 | 宿主每秒核对账本；一分钟内的调度延迟允许执行，不保证精确到秒 |
| 漏跑 | 默认跳过超过一分钟的漏跑；明确开启补跑时，在设置窗口内只执行最近一次，其他时间不逐次堆积 |
| 同规则重叠 | 默认跳过；可选合并保留一个最新待执行触发。等待批准/待核对仍属于活动执行 |
| 资源冲突 | 仍服从跨项目槽位、同仓库、重叠目录及共享资源组，不新增第二套执行器 |
| 事件去重 | 按来源Run固定键；不消费创建/恢复启用前的旧事件。自动化自身运行不再触发自动化 |
| 重启 | 规则和触发保留；原队列仍遵守启动恢复偏好。已接纳请求只对账，未知工具或进程不重放 |
| 关机或退出 | 本机宿主不运行时不执行；应用关闭继续使用原取消和清理链路，不安装Windows服务或唤醒电脑 |

SQLite事务将唯一触发与作业绑定。接纳前故障可使用原编号重试；接纳后响应丢失只读取原作业。队列满或关停时保留未接纳请求，不自动重跑已执行任务。目录、宿主配置或入口失效导致明确失败并暂停规则；不会静默用新环境执行。

## 权限与人工接续

宿主默认关闭持续授权。需要时，在运行TOML的`[permission_policy]`中明确设置`automation_grants = true`，再从页面审核规则；该开关本身不批准任何命令。宿主`deny`、规划只读、会话研究模式和严格审批继续约束实际动作。

持续许可绑定规则版本和授权代次、精确命令参数、实际目录、解析程序身份及显式脚本内容；验收只授权当前固定入口。实际放行记录规则来源、授权代次、参数摘要、入口和权限指纹，历史不依赖当前规则仍保有旧许可。Hook必须先通过原审核，再被规则明确选择；新工作树只能继承同定义、同内容及同执行入口的审核，不复制其他目录的宽泛信任。脚本传递依赖和命令网络行为不由静态指纹或工作树隔离。

未匹配许可、用户提问及新方案批准都进入原会话“需要处理”，清理后释放槽位。人工批准沿用原剩余预算和固定动作，接续仍关联原触发。保存新授权只作用于新授权代次，不静默批准已经等待的旧动作。

- 暂停：取消尚未开始的触发和排队请求，不停止在途工作；明确恢复只安排未来时间，暂停期间不作为离线漏跑补执行。
- 停止当前执行：暂停后续触发，取消活动运行及其后代；Git准备线程完成登记后再取消，不能强停未登记工作树。
- 撤销授权：清除持续许可并变更代次，旧运行不能继续新动作；活动执行按原机制停止。
- 编辑：完整替换定义，保留旧版本及触发历史；旧许可失效，未开始请求取消，新定义保持暂停。

命令按本机用户权限执行；本轮没有增加操作系统命令/网络沙箱。批准规则或方案不代表自动提交、推送或采纳成果，Git成果继续走原审阅、采纳与复验。

## 通知

每次执行都保留历史。主动通知用于实际文件变化/成果、失败、待审批、待核对及恢复；无变化的普通成功只保留历史。重复故障合并次数和最新入口。执行完成、验收通过及清理状态分别表达。

通知先落盘，Electron通过私有桥显示宿主固定文案，点击仅携带通知/作业UUID进入原作业。原生显示先持久认领，避免重启或刷新重复弹窗；系统拒绝弹窗时仍可在页面读取通知。Web共用持久列表，不依赖浏览器通知权限。旧轮产物、工作树及历史仍由原会话/成果管理入口保留和清理，不在定时器中删除未审阅成果。

## API与目录

- `GET/POST /api/automations`：列表/新建暂停规则；`PUT /api/automations/{id}`按版本完整替换。
- `POST /api/automations/preview`：计算未来五次时间，无执行副作用。
- `GET /api/automations/{id}/review`和`POST .../grant`：审核及保存精确许可。
- `POST /api/automations/{id}/actions/{enable|pause|run|stop|revoke}`：版本及请求UUID绑定的幂等动作。
- `GET /api/automations/{id}/history`：最近200次触发及真实结果引用。
- `GET /api/automation-notifications`和`POST .../{id}/read`：持久收件箱与明确已读。
- `src/agent_harness/automations/`：公开定义、时间计算、授权及触发服务；Web路由只负责接入。
- 运行清单及视图新增`automation`来源，普通运行为空；普通HTTP运行请求不能注入它。人工接续和子执行保留来源，不额外授予权限。
