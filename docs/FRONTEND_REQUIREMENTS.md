- 文档版本：0.3
- 更新日期：2026-10-20

- 交付阶段：V0.1基础控制台已交付；新增后端用户可见能力继续同步迭代
- 上游需求：[PRD](PRD.md)

## 1. 目标与实施顺序

提供可操作的本地 Web 界面，让使用者提交任务、观察执行过程、查看成果，并用于项目演示和故障排查。基础控制台采用 React、TypeScript、Vite 和 Ant Design，复用现有 Runner。

每次迭代先明确后端接口、事件与状态契约，在同一迭代内交付后端能力和对应页面，再完成联动验收。独立验收已有展示；上下文、恢复等后续能力按对应后端实现同步扩展。

启动、宿主配置与 HTTP/SSE 字段见 [控制台说明](WEB_CONSOLE.md)。本文维护页面行为和验收要求，不重复维护操作说明或每次测试数量。

## 2. 首版页面与功能

| 页面 | 必须提供的内容 |
| --- | --- |
| 任务列表与提交 | 展示运行标识、任务摘要、工作区、创建时间、执行和验收状态；支持刷新、状态筛选、打开详情；在提交表单中输入任务、选择后端支持的工作区与本次运行配置 |
| 任务详情 | 展示当前执行阶段与耗时、模型和工具调用次数、剩余额度、按顺序排列的事件、工具参数与结果、错误与结束原因；可取消运行中的任务；展示最终回答、产物列表及验收结果 |
| 运行配置 | 查看当前模型、已实现工具和预算限制；校验并应用本次运行的覆盖值；密钥来源只显示环境变量名称，不接收或回显密钥值 |

产物可预览或下载；长输出预览必须保留截断提示，并能打开已保存的原始记录。产物访问仅限该运行登记的产物和允许查看的记录，不能凭任意宿主路径下载文件。

任务列表的历史查看和页面刷新不触发工具重放，也不等于恢复执行。保存任务预设、技能管理和检查点续跑随后续 V0.2 功能交付，首批配置页只需查看及本次覆盖。

## 3. 状态与运行体验

- 复用后端的运行状态、事件、预算和验收契约。执行、验收与清理状态分别显示；只有 completed、passed 且清理为 not_needed 或 complete 时，才展示任务成功。未验证、验收异常或清理未知/不完整时不得展示为成功。
- 真实显示“等待模型响应、正在执行工具、正在验收”等阶段与已耗时，避免请求等待期间界面没有反馈；不得伪造百分比或事件。
- 模型调用次数与 HTTP 重试次数分开展示；缺失用量保持未知或不完整，不展示为精确零用量。
- 取消按钮只提交取消请求。后端确认结束前显示“正在取消”；最终保留用户中断、上游取消、内部异常、超时和清理结果等真实原因。重复点击或重试取消请求不能产生重复终态。
- 首批沿用单任务运行限制；已有任务运行时明确显示忙碌并拒绝新提交，不能让界面看似接受了实际未启动的任务。
- 提交、查询和订阅失败时给出可读错误，并保留表单输入；空历史、加载中与连接中断有对应提示。

## 4. 后端协作要求

前端通过任务 API 提交、查询和取消任务，通过 SSE 订阅执行事件。后端复用现有 Runner，不在网页服务里另写一套模型与工具循环。

后台任务生命周期独立于单个 HTTP 请求和浏览器连接。关闭页面、刷新或订阅断开都不能自动取消运行；后端服务重启后至少可以读取既有轨迹，是否能继续执行由后续恢复能力决定。

事件使用现有 run_id 和连续 seq；断线重连按已收到的序号补齐记录并去重，最终状态以持久化记录为准。前端可以根据后端时间计算等待时长，但不能由等待时长推断任务已经超时或成功。

模型密钥由后端环境变量读取，不进入前端包、接口响应或浏览器存储。网页填写的目录和配置由后端继续校验；浏览器无法选择的宿主目录不得假装成有效工作区。

### 4.1 同步变更与契约维护

每次修改后端代码，都检查前端影响；以下变化必须在同一迭代内完成对应前端更新：

| 后端变化 | 必须同步的前端内容 |
| --- | --- |
| 请求、响应或配置字段 | 接口调用、类型、表单、默认值、校验和错误提示 |
| 工具集合、参数或结果 | 配置中的可用工具、参数与结果展示、输出截断提示及产物链接 |
| 运行、验收或清理状态及结束原因 | 状态标签、阶段提示、操作可用性、成功判断及异常说明 |
| 事件类型、载荷或序号规则 | 事件解析、时间线、重连去重与最终记录核对 |
| 产物索引或访问规则 | 列表、预览、下载与失败反馈 |

每个受影响功能都同步更新相关测试和需求、接口或使用文档。版本或功能迭代的 Plan 列出上述映射及验收场景；确实不影响前端的内部后端变更，交付时说明原因。接口字段说明包含业务含义、单位、默认值、可选性和状态约束，前端不自行推断未知值。

### 4.2 独立验收的页面映射

下表已在前端共享类型、时间线与验收面板接入；完整定义见 [技术设计第9节](TECH_DESIGN_V0.1.md#9-独立验收协议与状态收尾)。

| 后端字段/事件 | 对应前端行为 |
| --- | --- |
| verification=null | 展示未运行验收或旧记录无详情；结合validation_status与跳过原因展示，不推断失败 |
| verification.status与顶层validation_status | passed/failed/error分别显示验收通过、产物未通过、验收异常，保持两者一致 |
| verification.reason / exit_code | 展示受控原因和验收子进程退出码；None表示没有拿到进程退出码 |
| verification.elapsed_ms / stdout / stderr / truncated | 毫秒耗时、有界双流预览与截断提示；stderr非空不能自行推断验收失败 |
| verification.artifacts | 展示验收原始双流引用，经受限产物接口打开；沿用location/path/kind |
| verification.timed_out / cancelled / output_limit_exceeded / cleanup_status | 明确显示超时、取消、输出超限和清理结论，保留模型已经完成的执行状态 |
| execution_completed | 阶段切换为执行已完成，等待验收或最终收尾；不能提前展示整项成功 |
| verification_started | 显示正在验收与自身秒级预算；连接中断不取消后台运行 |
| verification_result | 展示宿主详情；模型回答保留原文，其内容不能覆盖验收字段 |
| verification_skipped | reason=not_configured或execution_not_completed；明确展示未验收原因 |
| run_finished | 按持久化最终结果确认结束；总超时/取消发生于验收时，执行仍completed、验收为error |

验收器采用后端维护的预设，前端提交预设标识，不接受模型或网页传入任意宿主 argv。当前通过/api/options读取宿主登记项，提交workspace_id/verifier_id；实际接口及单位约定见 [控制台说明](WEB_CONSOLE.md#5-http契约)。

## 5. 首批验收标准

| 编号 | 场景 | 可观察的通过条件 |
| --- | --- | --- |
| F01 | 网页提交正常任务 | 从页面提交一个当前支持的预置样例，获得运行标识并进入详情；产生与 CLI 同契约的记录、成果和真实验收状态；日志样例独立验收通过，普通无验收任务明确保持unverified |
| F02 | 实时执行与等待 | 执行中可看到当前阶段、已耗时、模型/HTTP/工具计数和顺序事件；工具输出与真实记录一致 |
| F03 | 状态与产物 | 独立展示执行和验收状态；能查看回答、预览或下载登记产物；没有验收入口时不展示为成功 |
| F04 | 历史与重连 | 刷新、关闭再打开页面或短暂断网后，仍可查询任务；重新订阅补齐事件且不重复工具动作；断开连接不取消任务 |
| F05 | 主动取消与异常 | 网页取消经后端确认后结束；超时、工具错误和内部异常有真实原因及清理结果，保留取消前已保存输出 |
| F06 | 无效配置与忙碌 | 无效路径或参数在启动前给出错误；运行槽位被占用时明确拒绝新任务，不生成假运行状态 |
| F07 | 凭据与访问边界 | 页面与接口无模型密钥；配置只接收支持字段；不能通过产物请求读取任意宿主文件 |
| F08 | 前后端同步回归 | 每项影响前端的后端变更均有对应调用、类型、页面或交互更新；通过受影响的契约检查与页面联动场景，核对实际请求、事件和最终展示，相关文档同步更新 |

每个切片按实际变更选择上述场景，并保留联动验收结果；基础控制台整体交付时覆盖 F01—F08。仅接口可调用或后端测试通过，不算对应前端功能验收完成。

## 6. 后续范围

控制台首版聚焦本地单用户、单任务操作。登录、多租户、拖拽工作流、复杂配置编辑器、可视化技能管理和多任务队列不属于本批交付。V0.3 再增加失败分析、候选对比、版本晋级与回滚页面。

## 7. 验证记录与已知限制

已有测试结果、真实模型记录和 F01—F08 证据映射集中维护在 [控制台验证记录](WEB_CONSOLE.md#7-已保留的验证证据)。新增迭代在完成实际检查后追加日期与结果，不将历史结果当成新验收。

普通工作区历史产物仍是当前路径引用，后续覆盖会改变下载内容；不可变产物快照尚未实现。工作区由宿主登记，网页不提供任意宿主文件浏览器，自动续跑也未实现。当前阶段与后续路线见 [项目概览](../PROJECT.md)。


## 8. 真实项目任务与审阅

任务表单增加项目模式：读取宿主登记的项目、基线提交、未提交状态与测试命令。提交项目编号和基线，不夹带普通工作区或验收器编号。无项目登记时原表单继续可用；不可用项目显示明确原因。基线说明必须写明未提交改动不带入。

详情新增代码改动页签：列出变更文件、基线、独立目录与纯文本 diff，显示二进制/预览截断标记并提供完整补丁下载。保留、丢弃及其失败反馈保持在当前任务；丢弃需要明确确认。运行中、快照未就绪或错误时禁用不适用操作，不能将测试通过显示为已接受代码。保留后不暗示已合并原分支，丢弃后继续显示历史测试与保存补丁。

联动验收覆盖项目表单、正确/错误修改的真实测试、取消后的改动、刷新与服务重启后待审阅结果，以及保留/丢弃操作与原目录保持一致。API与业务边界见 [代码任务与审阅](PROJECT_TASKS.md)，证据集中于 [控制台说明](WEB_CONSOLE.md#7-已保留的验证证据)。
