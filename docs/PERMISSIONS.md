# 权限控制与动作审批

本轮按 2026-11-02 用户批准的 C12＋C05 Plan 实现。桌面、Web 和 CLI 共用执行前判定；人工动作审批首版在桌面和 Web 会话完成。审批不提供操作系统命令沙箱，Git 工作树也只隔离代码目录。

## 1. 模式与宿主上限

| 会话模式 | 项目读取 | 文件写入、编辑 | 本机命令 | 宿主验收 |
| --- | --- | --- | --- | --- |
| `research`：仅研究 | 允许 | 拒绝 | 拒绝 | 不执行 |
| `workspace_edit`：工作区编辑，默认 | 允许 | 允许 | 默认审批 | 默认审批 |
| `strict`：严格审批 | 允许 | 审批 | 审批 | 审批 |

以上还受工具启用、宿主策略和目录范围限制。宿主配置示例：

```toml
permission_mode = "workspace_edit"

[permission_policy]
read = "allow"
write = "allow"
command = "ask"
verification = "ask"
read_roots = ["."]
write_roots = ["."]
approval_ttl_seconds = 1800
```

宿主判定为 `allow / ask / deny`，拒绝优先；会话可以收窄，页面不能提交 `permission_policy`。宿主明确设置 `command` 或 `verification` 为 `allow` 时，工作区编辑模式下可预授权对应入口；严格审批仍要求逐项确认。首版不提供命令前缀规则、永久授权或自动风险审查。读取 `ask` 暂按拒绝处理，不提供读取审批。

目录只接受工作区内无通配符的相对前缀，空列表表示没有相应文件范围。原目录和隔离工作树分别解析；符号链接、junction、Windows设备名及记录目录继续由 `Workspace` 核验。递归搜索与列表逐项过滤。文件工具不能写入 `.git`、`.agents` 或 `.codex` 路径。根 `AGENTS.md` 同样服从读取范围；已有必需指令无法读取时停止，不静默忽略规则。

规划期间仍禁止写、编辑、命令、任务修改和记忆候选，允许研究、计划操作与查询；规划控制器和权限模块共用同一份阶段规则。批准计划不会解除动作审批。子 Agent 继承父目录与宿主约束，再与只读角色、父工具集合取交集；不能申请写入、命令或继续委派。技能、模型正文和用户普通消息不能修改授权事实。

## 2. 执行入口与动作冻结

执行顺序为：参数校验 → 规划及角色核验 → 统一权限判定 → 必要审批 → 真实开始事件 → 副作用 → 真实结果。`tool_requested` 计接纳次数，`tool_started` 只表示已经通过检查、即将执行；拒绝和等待不冒充开始或成功。

审批覆盖 `write_file`、`edit_file`、`run_command` 和 Runner 直接启动的 `verification`。项目公开测试与独立验收都不能绕过命令审批；模型结束不等于已经运行验收。仅研究时跳过检查并保持未验收。宿主管理目录、Git证据采集、取消清理及用户主动下载等基础设施操作沿用各自受控入口，不作为模型任意执行接口。

每个待审批动作保存 UUID、会话和来源 Run、原调用编号、规范化完整参数、实际工作区身份、权限与规划版本指纹、解释器和验收配置、创建/到期时间。文件绑定缺失状态或内容指纹与对象身份，覆盖写入还固定原文本以便审阅；非 UTF-8 原文件明确提示无法展示文本。命令绑定实际工作目录、程序路径和程序身份，显式普通脚本另保存有界指纹。

这些核验不能推断命令会读取的全部脚本、模块和外部资源。批准本机进程后，进程仍按操作系统权限访问文件与网络；文件工具的目录限制不能宣称约束了进程的所有行为。现有子进程环境白名单、超时、输出上限与进程树清理继续生效。

## 3. 等待、决定与确定接续

需要审批时，先提交不可变请求事件，再保存受保护数据库记录；保存失败不执行动作。当前调用返回 `approval_required`，同批后续调用均标记 `skipped_action_approval`。父运行收拢子研究、固定差异与产物，以 `waiting_input / action_approval` 结束并释放执行槽。

会话提供“批准本次 / 拒绝 / 取消等待”。批准只绑定页面看到的动作编号与指纹，不允许夹带新参数、配置或计划决定；普通文字“批准”“继续”不消费许可。默认有效期30分钟，包含人工等待和排队。过期未决定的动作仍可拒绝或取消；已批准但排队过期的许可明确失效。

批准与唯一接续作业在同一 SQLite 事务提交。出队重新核对来源、当前目录、宿主配置及动作输入。宿主先执行保存的原调用，再把真实结果交回模型，不先请求模型重新生成动作。接续工具消息标记 `host_action_resume`，有独立调用编号和原动作引用，不伪造新的供应商响应。原批次其他工具不连带恢复。

验收接续先执行保存的检查，不要求模型重新回答。公开检查失败后，原有有限修复流程可以继续；隐藏检查不反馈模型。拒绝和取消只保存明确决定及终态，不调用模型、工具或验收，也不回滚此前修改。用户需要替代方案时另发普通消息。

## 4. 预算与历史

纯动作审批接续沿用整条链的剩余模型、工具、活动时间和修复次数，不因创建新 Run 清零。原动作在请求时已计工具次数，批准执行不重复计数；人工等待和排队不计活动时限。原动作可在没有剩余模型请求额度时执行，但之后明确以额度耗尽结束，不能凭审批增加总结请求。

每段 Run 保留自身次数、Token和活动时长；`permissions.spent_*` 保存此前各段累计消耗及已知用量完整性。普通新要求与规划接续继续采用其既有预算协议。自动修复仍最多两次，审批不能借机增加次数。

旧轮 `run.json`、事件、结果、产物与差异不被新决定覆盖。当前动作状态由工作数据库查询；历史检查器使用当轮固定状态，旧快照中的“待批准”不表示现在仍可操作。后台中心分别显示待审批、已批准待执行和决定已处理。

## 5. 存储与故障边界

`<runs_root>/.work/work.sqlite3` 的 `permission_actions` 与作业共用事务，保存不可变动作、决定、幂等请求和消费归属；RunStore 保存执行事实与终态快照。工作事件包含 `permission_updated`；运行事件包含 `permissions_prepared`、`permission_requested` 和 `permission_resuming`。不建立第二份可编辑授权文件。

| 情况 | 行为 |
| --- | --- |
| 同编号同决定重试 | 返回原作业，不重新执行 |
| 同编号不同载荷、旧父轮或旧动作 | 冲突拒绝 |
| 批准与拒绝并发 | 一个决定胜出 |
| 刷新或重启 | 只读恢复，不自动批准；遗留队列需明确恢复 |
| 已批准但尚在排队，用户停止作业 | 同事务撤销许可；恢复队列不执行旧动作 |
| 出队前审批过期或配置变化，确认尚无 Run | 明确失败并使许可失效，不伪造结果不明 |
| 已认领且缺少可信回执 | 标记 `unknown`，队列待核对，不自动重放 |
| 回执已落盘、审批状态未更新 | 持执行锁启动对账，从对应执行日志补记事实 |
| 记录不可核对或写入失败 | 停止，不补造批准或成功 |

SQLite与文件日志不能跨存储原子提交，采用唯一编号、指纹、执行前认领和启动对账；不能宣称任意外部副作用恰好执行一次。当前也不保证阻止用户或其他本机进程修改文件。

## 6. HTTP、页面与CLI

决定沿用唯一作业入口：

```json
{
  "request_id": "同一决定重试保持的UUID",
  "parent_run_id": "产生当前等待的最新Run UUID",
  "followup": {
    "request_id": "与外层相同的UUID",
    "prompt": "批准本次动作",
    "action_decision": {
      "action_id": "动作UUID",
      "fingerprint": "页面审阅的64位SHA256",
      "action": "approve"
    }
  }
}
```

`action` 为 `approve / reject / cancel`。决定不能同时提交 `decision`、`mode` 或非空配置。网页保留未确认请求，网络重试只能确认原编号。

`GET /api/runs/{id}/permissions?historical=false&offset=0&limit=50` 返回固定权限视图、宿主策略和会话动作分页；`historical=true` 固定当轮请求，不回查新决定覆盖旧快照。所有接口复用原有同源、桌面认证与会话生命周期核验。查询不自动执行、批准或恢复队列。

页面显示后端计算的实际权限、目标、原内容/编辑片段、完整命令参数、实际程序和到期时间。当前待审批动作轮询状态，已决定或已批准排队的动作不再提供第二次批准；历史仅阅读。模型、技能、预算等实现细节不混入审批正文。权限模式选择只影响新任务或下一条普通消息。

CLI同样拦截动作，输出待审批原参数并返回4；首版没有CLI动作审批恢复命令，也不承诺无来源CLI记录可直接由Web接续。完整审批任务请在桌面或Web创建。
