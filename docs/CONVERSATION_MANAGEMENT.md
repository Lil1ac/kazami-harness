# 会话管理

会话是管理单位，包含首轮及全部追加运行。列表、侧栏、详情和后台工作共用服务端有效标题与整理归属；管理操作不修改原用户消息、运行状态、事件时间或验收结论。

## 操作与界面

- 重命名：1—200字符，去除首尾空白，拒绝控制字符；恢复默认名称使用首条需求的精简文本，不调用模型。
- 移动：选择已登记项目或未分组。只影响导航、筛选，后续执行仍使用原目录、原项目记忆和原批准范围；弹窗和详情明确说明。
- 置顶：正常、归档列表先按置顶时间，再按最后真实运行活动排序。整理和浏览不伪造活动时间。
- 归档：可阅读，停止发送、计划决定和会话任务修改；取消归档不自动执行。
- 删除：整段会话进入回收站。恢复保留名称、归属和置顶，并恢复删除前的正常/归档状态；回收站按删除时间排序。
- 彻底删除：仅回收站单条确认，额外勾选永久删除；失败可重试。未完成作业和未知清理先处理，保留的独立工作树必须先恢复会话并明确丢弃。
- 搜索和批量：服务端搜索标题及首条需求，先筛选排序再分页；分类与筛选保存在URL。批量移动、归档、删除和恢复只处理当前页明确选择的项，接口上限50条；逐项返回结果，失败项保留选择及原因。彻底删除不提供批量入口。

## 存储与接口

复用`.work/work.sqlite3`：`conversations`保存可变管理属性，`conversation_operations`保存操作回执。轮次关联继续使用`.sessions`及各Run清单。尚无人工操作时从首轮推导正常状态、精简标题及已登记来源归属，读取不创建会话元数据；不提供旧协议迁移或前端标题拼装。

| 接口 | 行为 |
| --- | --- |
| `GET /api/conversations` | `state=active/archived/trashed`、`q`、`project_id`、`ungrouped`及原状态/分页参数 |
| `GET /api/conversations/{session_id}` | 统一管理视图，包括版本、权限、禁止原因、轮次数及记忆引用数 |
| `PATCH /api/conversations/{session_id}` | `rename/move/pin/unpin/archive/unarchive/trash/restore`，附UUID请求编号及管理版本 |
| `POST /api/conversations/batch` | 明确选择的会话和各自版本，逐项成功/失败回执 |
| `DELETE /api/conversations/{session_id}` | 请求编号、版本及`confirm=true`，单条受控清理 |

写操作使用`request_id`和非负`expected_revision`。版本冲突返回409；同编号同载荷重试复用回执，不同载荷拒绝。网络结果未知时前端保留草稿和原请求；用户明确刷新状态成功后，再确认使用新版本及新编号。管理变更和`conversation_updated`事件同事务提交，全站单个work-stream同步多窗口，列表和恢复页另有轮询。

移动、归档、删除在宿主管理锁和SQLite事务内重新核验全部关联作业、准备意图、收尾及清理状态。作业接纳和出队也要求会话正常。执行中允许命名和置顶；归档和删除后不能经任务工具、队列或计划决定绕过。

归档运行可读；回收站、清理中及已清理运行的正文、事件、SSE、产物、补丁和桌面下载返回410及稳定会话编号，旧链接显示恢复入口。后台作业及全站事件隐藏已删除会话正文。管理记录损坏返回受控错误并保留记录，不擅自重建默认状态。

生命周期错误响应及前端API读取均禁止HTTP缓存，避免浏览器沿用可启发式缓存的410；恢复后显式重读原链接和完整会话，清除查询中的旧错误，保持所选轮次且不自动执行。

## 彻底清理

首次确认持久保存`purging`状态、请求及冻结UUID清单，核对每轮所属会话。白名单仅包含受保护运行根内的会话JSON、Run目录、原目录前后快照、变更记录、固定产物和项目证据目录；拒绝越界、符号链接及Windows重解析点。项目目录和`worktrees_root`不在清理范围，工作树先由审阅机制明确丢弃。

文件清理成功后移除会话任务、操作正文、动作审批正文与许可及关联事件；作业仅保留身份、原载荷摘要和结果状态，阻止旧请求重新执行。删除墓碑保留会话/运行UUID及清理结果，不保留需求正文。中断后重启仍使用冻结清单，不从残留目录推断新范围，也不自动恢复执行。

另存项目记忆独立保留。来源属于已开始彻底清理的会话时，当前列表和修订视图标记来源不可用，相关事实需复核；旧Run固定上下文和记忆修订正文不被追溯改写。

## 验收

自动回归覆盖真实HTTP、队列、普通目录续轮、Git独立工作树、版本/幂等、忙碌限制、删除访问、记忆来源、重启及清理失败重试。前端验证菜单权限、确认、草稿、未知请求复用、刷新版本保存及批量部分失败，并执行类型检查和生产构建。

页面使用`tests/helpers/serve_conversation_management_fixture.py`；仅模型响应确定化，API、Runner、文件工具和持久化真实执行，检查桌面和390px窄屏。最新实测结果统一记录于[控制台说明](WEB_CONSOLE.md)。
