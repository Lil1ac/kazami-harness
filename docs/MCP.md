# 受控 MCP 工具接入与联网研究

本轮覆盖 C10 的外部连接、工具发现与调用，以及 C17 的官方文档研究首版。桌面、独立 Web 和 CLI 共用 Runner、权限、工具预算及固定历史。Skills 的自主激活与附属资源、MCP 资源/提示模板浏览、OAuth、浏览器及图像能力仍属后续范围。

## 使用流程

1. 打开“运行配置 → 外部工具连接”，添加连接。远程使用 Streamable HTTP；本机使用 stdio，填写绝对程序、参数数组和启动目录。
2. 保存只登记配置，不会连接或启动进程。核对实际配置后点击“已核对，允许连接”。stdio 是受信任的本机程序，可按系统权限访问文件与网络，不提供操作系统沙箱。
3. 点击“连接并发现工具”。成功后查看真实工具说明和参数结构；需要在规划或研究阶段使用时，人工勾选“研究阶段与子 Agent 可用工具”并保存。服务自报的 `readOnlyHint` 等注解不授予权限。
4. 明确启用连接，在新任务“高级设置”或会话“下一轮设置”中选择本轮工具，最多16项。每项绑定当时的连接和定义指纹。
5. 默认每次调用等待具体参数批准。审批显示实际端点、远端工具名、原参数与定义；批准后宿主接续原动作，沿用剩余预算。
6. 在“本轮详情 → 结果”查看外部资料、实际来源链接、结果和当轮配置快照。刷新、停用或后续改配置不会替换历史证据。

公开文档服务可使用 `https://developers.openai.com/mcp`，选择 `search_openai_docs` 和 `fetch_openai_doc`。该服务只提供官方文档搜索与内容读取，不代表 Harness 接入了 OpenAI 模型，也不会代替用户调用 OpenAI API。

## 通用网页搜索与原文读取

在「运行配置 → 外部工具连接」添加远程 Streamable HTTP 连接，地址填写 `https://mcp.exa.ai/mcp`。按现有流程审核连接、发现工具并启用。用于仅研究模式时，先在「研究阶段与子 Agent 可用工具」勾选并保存 `web_search_exa` 和 `web_fetch_exa`。Exa 提供有频率限制的免密钥试用，凭据字段可留空。 [Exa MCP 官方说明](https://exa.ai/docs/get-started/exa-mcp)

在任务高级设置或会话下一轮设置中选择上述两个工具。`web_search_exa` 搜索公开网页并返回结果摘录，`web_fetch_exa` 按所选 URL 读取正文。默认策略下，先核对并批准要发给 Exa 的查询或 URL。任务结束后，可在对应轮次的「结果 → 外部资料与调用」查看链接和工具回执。Exa 的来源列表使用结果条目报告的页面地址，正文中提到的其他链接保留在原始回执中。

## 认证与宿主策略

HTTP 支持无认证、Bearer Token 和 `X-API-Key`。连接配置只保存凭据环境变量名；独立 Web 和 CLI 从宿主环境取值。桌面还可以在对应连接下加密保存凭据，由 Electron `safeStorage` 按连接分区存储，页面不能回读。stdio 只额外传递配置中明确列出的变量名；不自动继承模型密钥。

凭据写入或清除先撤销旧审核和工具目录，原生保存期间禁止重新审核或启用。失败也不会恢复旧授权。用户须重新审核、发现、启用并选择新版工具。程序参数和 URL 不应包含秘密；URL 禁止用户信息、查询参数及片段。远程端点必须为 HTTPS，仅环回允许 HTTP。环回连接绕过宿主代理；远程尊重代理配置并支持 SOCKS。

宿主 TOML 的权限上限：

```toml
[permission_policy]
external = "ask" # 默认逐项审批；allow 允许已选工具，deny 禁止外部连接与调用。
```

研究模式和规划阶段只开放人工审核的研究工具，仍受 `external` 和读取上限约束；严格模式始终逐项审批。开发子 Agent 只继承父本轮已选、人工审核的研究工具。只读子 Agent 没有动作接续检查点，因此仅在宿主 `external="allow"` 且非严格模式时使用这些研究工具，其余情况拒绝，不产生孤立审批。自动化运行始终拒绝 MCP 工具，本轮不增加外部工具持续授权。

CLI 可在同一 `--runs-dir` 下引用页面已登记、审核并启用的连接。运行配置的 `mcp_tools` 使用 `/api/options` 返回的 `name` 与 `fingerprint` 对；空列表明确关闭。默认 `ask` 遇到外部动作时仍返回既有等待退出码4，完整审批交互使用桌面或 Web。

## 执行与故障边界

- 使用官方 Python SDK 2.3 系列及锁文件，支持协议协商；不自写 JSON-RPC，不为旧产品记录增加兼容层。
- 工具使用 `mcp_` 哈希命名空间，与内置工具分开；动态 Schema 经校验，禁止通过 `$ref` 加载外部文档。每轮定义完整计入现有模型输入预算。
- 连接、目录及调用分别有时限；调用与父子执行共享原工具次数、总时限和取消机制。本机服务占用宿主进程槽，退出时由 SDK 有界清理进程树；每次发现/调用结束均关闭本次客户端，不保留无归属后台进程。
- 真实调用前重新校验启用状态、配置指纹、本机程序/显式入口脚本及目录身份，再从服务发现当前工具定义。定义变化不执行旧参数，连接停用并要求重新发现审核。
- 认证错误、连接/发现失败、外部工具明确错误和结果不明分别表达。连接重试由用户明确发起；业务工具请求不自动重放。
- 请求已发出后超时、传输失败或无法核验结果，视为结果可能已经生效；停止当前执行并停用连接。取消也保留未知结果证据。核对远端后重新发现并启用仅授权新调用，不重放旧请求。
- 宿主重启只读取原日志；既有工具开始/结果及审批认领机制负责标记缺失回执，不自动续跑。外部动作不提供“恰好一次”执行保证。
- 每个服务最多128个工具，目录最多512 KiB，单条说明最多16000字符。结果超过256 KiB保留有界预览并标记截断，不能当作完整文档。凭据及明确传入的私有环境值从结果中隐藏；定义中出现这些值则拒绝保存。

外部服务可能更新实现而不改变 Schema；本轮只能固定连接配置、已发现定义、本机显式入口身份和实际回执，不能核验远程实现版本或约束全部传递依赖。人工研究标记是授权判断，不是操作系统只读保证。

## API 与持久事实

| 入口 | 语义 |
| --- | --- |
| `GET /api/mcp` | 只读连接目录、可选工具、宿主上限 |
| `PUT /api/mcp` | 新增或绑定原指纹替换配置；撤销旧审核 |
| `POST /api/mcp/{id}/review` | 明确信任、研究工具审核、启用或停用 |
| `POST /api/mcp/{id}/discover?fingerprint=…` | 对已审核版本建立连接并发现工具 |
| `PUT /api/mcp/{id}/credential` | 仅桌面写入或清除分区秘密；撤销旧授权 |
| `GET /api/runs/{run_id}/mcp` | 读取该轮完整外部快照与调用证据，不受实时事件窗口裁剪 |

公开配置保存在运行根 `.extensions/mcp.sqlite3`。SQLite事务和指纹比较防止并发覆盖；审核、发现、授权和启停递增代次，撤权后再启用也不会使旧批准复活。`mcp_prepared` 固定实际配置、研究标记、工具定义和入口身份，`mcp_call_started/result/failed` 固定调用与来源。来源从实际结果抽取，不从当前端点推测；无来源时不伪造链接。外部结果只作为数据，不提升为系统指令。
