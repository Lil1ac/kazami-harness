# 跨项目后台调度与安全恢复

本轮将 C06 的全局串行队列改为受资源约束的本机并发调度，并同步交付 C15 所需的状态观察。桌面、Web、CLI 与成果采纳复用原 Runner、权限、验收和持久记录；没有新增执行后端。

## 使用方式

后台工作按“需要处理、运行中、排队、已结束”分组，显示已占槽位和总容量。排队项说明等待槽位、项目资源或未知结果，并可进入占用作业；停止只影响所选作业及其后代。

默认允许两个独立项目同时工作。同一会话、同一 Git 公共目录的不同工作树、父子目录及宿主登记的共享资源组仍串行。一个受阻项目不会挡住后续可运行项目。工作树只隔离代码目录，不提供命令沙箱；所有规则仅协调使用同一运行数据目录的受控入口。

“启动后继续未开始的队列”默认关闭。开启后，宿主启动时重新核对来源、目录及仓库身份、解释器、项目测试和权限，再调度尚未开始的请求。修改此选项不解除当前暂停，也不批准待处理动作。关闭桌面仍取消全部活动工作并等待清理，未开始请求留在队列；电脑或应用退出后不继续执行。

## 宿主配置

独立 Web 使用 `harness serve --web-config web.example.toml`；桌面启动参数也支持 `--web-config <文件>`。桌面固定使用应用自带前端及应用数据目录中的工作树，不从该配置切换界面资源。

```toml
# 主 Run 和成果集成作业合计容量，1—8，默认 2。
max_concurrent_runs = 2
# 所有主 Run、摘要、子 Agent 和 Teams 共用，1—32，默认 2。
max_model_requests = 2
# 命令、Hook 和宿主检查共用，1—32，默认 4，清理完成后才释放。
max_processes = 4

# 共享数据库、端口等资源的项目需要显式声明；路径相对此文件，目录必须可核对。
[serial_resource_groups]
database = ["../backend", "../worker"]
```

普通目录可以在未安装 Git 时使用；识别到仓库标识后必须有 Git 才能核对公共目录。组名不能以双下划线开头。配置只协调执行归属，不授予目录或命令权限。改变分组、仓库或目录身份使已排队的旧快照失效，用户核对后重新提交；不会静默采用新环境执行。

## 调度与资源协议

1. 接纳时冻结请求编号、公开配置、记忆策略、目录和 Git 公共目录身份及共享资源组。
2. 按接纳顺序选择满足条件的请求；跳过资源阻塞项，达到容量上限后继续等待。
3. SQLite 同一事务写入资源归属并将作业推进到 preparing。一个宿主持有数据目录操作系统锁，其他宿主或 CLI 不能抢占它。
4. 准备参数直接绑定作业和 Run；活动句柄按 Run 存储，会话内准备及线性接续单独核验。
5. 桌面/Web 的模型请求及真实进程通过异步上下文继承宿主容量，包括摘要、子执行、Hook 和验收。等待容量仍受所属运行的预算和取消约束；CLI 一次运行独占宿主执行锁，沿用单运行预算与原有子执行限制。
6. 验收、后代清理、差异与产物固定后，保存作业终态并释放资源。等待用户且已清理的执行释放槽位；接续重新核对授权。

成果采纳同时占用来源及目标资源；集成作业之间保持串行，避免共享集成控制器串线。人工保留、丢弃及补捕获也申请来源资源，文件线程结束后才释放。父任务内部已有的受控子工作树并行机制继续使用原归属，不被当成新的跨会话主 Run。

Git 资源探测显式使用空标准输入和受限子进程环境，避免继承 Electron 私有协议流或模型凭据。操作系统锁覆盖全部正在执行的本机作业，SQLite 租约保存跨重启的归属与未知状态。

## 恢复边界

| 已保存事实 | 处理 |
| --- | --- |
| 尚未认领的 queued 请求 | 按用户启动偏好或明确恢复操作，重新核验后执行 |
| Run 已有可信终态，作业仍标记运行中 | 对账为实际终态，不重调模型或工具 |
| 已认领但缺少可信结束回执 | 标记 needs_review，相关租约标为 unknown |
| 进程清理 unknown / incomplete | 保留相关资源阻塞，不把取消当成已清理 |
| 人工工作树操作关联的旧 Run 已完成 | 旧 Run 不能证明这次操作完成，仍需核对 |
| 另一宿主仍持有操作系统锁 | 不修改其执行状态或夺取归属 |

未知结果仅阻塞相关项目、会话或共享资源组。用户确认进程停止、工作区已核对后可解除该作业阻塞；涉及写回的成果采纳继续要求逐文件对账。原请求不重放，需要继续时另发新请求。一般运行中断仍通过核对后的普通消息接续；本轮不承诺任意步骤恢复、原进程现场恢复或外部副作用恰好执行一次。

## API 与页面契约

- `GET /api/options`、会话列表和会话详情采用 `active_run_ids`，删除旧 `busy_run_id`。会话详情只返回本会话活动运行，其他项目不阻止发送。
- `GET /api/jobs` 增加 `scheduler`：容量、活动作业、暂停状态和 `resume_on_start`。
- 宿主保存冻结的资源快照，公开作业增加 `blocked_reason`、`blocked_by`；资源内部身份不进入页面契约，状态变更继续通过 work events 和查询观察。
- `PUT /api/queue/settings` 接收 JSON `{"resume_on_start": true|false}`，保存明确偏好，不执行恢复动作。
- `POST /api/queue/resume` 恢复可执行队列；未知资源保持局部阻塞。
- 单项取消、运行中消息、命令停止、子 Agent 与 Teams 控制均按实际 Run 定位。

没有保留单槽数据结构、旧字段别名或旧队列记录迁移层；历史验收文档中的单槽描述只代表对应日期的实现。
