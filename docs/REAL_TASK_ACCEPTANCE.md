## 5. 实际交付与后续问题

验收副本的累计修改仅涉及：

- `src/agent_harness/tools/files.py`：递归 glob 修复，`ignore_case` 参数与大小写折叠。
- `tests/test_file_mutations.py`：针对 glob、参数、大小写和 Unicode 的回归。
- `docs/TECH_DESIGN_V0.1.md`：工具语义说明。

完整交付见 [最终补丁](../.runtime/real-task-acceptance-20261026/evidence/final-delivery.patch) 和 [固化源码](../.runtime/real-task-acceptance-20261026/evidence/final-delivery/src/agent_harness/tools/files.py)。这些修改只存在于验收副本；采纳前需要审阅补丁，并按迭代约定确定范围。

本轮得到以下有证据的问题，后续一次只选择一项提交 Plan：

1. **测试环境说明不足**：命令的 cwd 正确，共享解释器中的 editable 安装却指向原仓库，模型一度测试了另一份源码。补充 `pythonpath=src` 后正确；应先明确项目解释器、源码导入路径和测试命令，避免仅凭工作目录判断环境正确。
2. **读取和回读开销**：首轮包含 5 次 `read_context`，默认分页结果及包装元数据可能超过 8192 字节内联阈值，带来额外回读。可以提出受限配置候选比较，但提高阈值的收益尚未验证，不据此直接改默认值。
3. **编辑和测试收尾需要指导**：LF/CRLF 不一致导致精确编辑未命中；新增测试中的预算计数断言多次修正，也消耗了轮次。应保留精确替换与预算保护，先改善可执行说明和测试范围，再比较干预次数与调用开销。
4. **网络错误需进一步复现**：有限重试后仍有两次失败，普通消息接续有效；没有证据要求新增检查点、无限自动重试或通用恢复框架。

本次没有开展基线/候选的公平性能比较，没有实施验收后自动修复循环；执行中的“命令失败 → 反馈模型 → 修改 → 重测”已实际发生。命名预设、Docker、通用插件框架和自动诊断平台仍按 PRD 的实际需求边界安排。
