# Agent Harness 控制台

React、TypeScript、Vite、Ant Design 构成工作台界面，任务仍由 Python 后端的同一个 Runner 执行。前端不保存或回读模型密钥，也不执行模型工具。

主要产品入口是 Electron 桌面端，复用本目录的构建产物；启动命令见 [桌面端说明](../docs/DESKTOP.md)。桌面设置跨启动保存，模型密钥只在用户输入期间位于组件内存，由宿主进行系统加密，接口不回读正文。浏览器服务仍使用临时配置覆盖。附件下载、文件定位、原生目录选择和外链由桌面宿主统一承接；任务协议、规划批准和 SSE 使用同一套实现。

界面通过侧栏项目树、中央输入与会话、按需运行详情组织信息。首页只展示新建输入和最近会话，执行目录紧邻输入框；Git 分支和提交放在高级设置。项目页提供持久化解释器与测试配置；任务表单只保留当次选项。详情分为结果、文件、诊断：文件合并差异与产物，诊断收纳轨迹、上下文及运行配置。详情普通入口默认收起，显式 `tab` 或 `inspect` 深链接直接展开；桌面使用右侧栏，窄屏使用抽屉，跨断点收起时保留消息和草稿。设置页保留一次配置生效范围说明，单位、错误与风险提示仍就近展示。列表统一使用 /api/conversations；/api/options 的 recent_projects 是唯一项目列表。单轮详情与 SSE 契约继续复用。

## 开发与检查

需要 Node.js 22.12 或更新兼容版本。Windows 下可用 `npm.cmd` 避免 PowerShell 脚本执行策略影响。

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

开发页面是 `http://127.0.0.1:5173`，`/api` 自动代理到 `127.0.0.1:8765`。Python 服务的启动命令见 [项目根 README](../README.md#启动网页控制台)，宿主配置与 HTTP/SSE 契约见 [控制台说明](../docs/WEB_CONSOLE.md)。构建后 `dist/` 由 Python 服务直接提供，普通路由刷新也由后端返回 SPA 入口。

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run format
```

`typecheck` 与 `build` 独立执行。`test` 是离线单次运行，不访问真实模型；默认最多并行三个 worker，避免 Windows 上 Ant Design/jsdom 同时加载争用资源。安装时如果旧版 npm 出现 `edgesOut` 依赖解析错误，可以使用临时 npm 11：`npm.cmd exec --yes --package=npm@11 -- npm ci`，无需修改全局 npm。

## 代码从哪里读

- `src/types.ts`：对应 Python 数据模型与 HTTP 接口的类型，单位和可选字段有中文说明。
- `src/api.ts`：HTTP 请求、受控错误、产物 URL，页面不直接拼任意宿主路径。
- `src/pages/`：新建/全部会话、项目、会话详情与运行配置页面。
- `src/components/`：提交表单、运行状态、事件轨迹、产物、项目代码审阅和验收面板。
- `src/diff.ts` 与 `FileChangesPanel`：解析 Git/普通 unified diff，按文件分组并显示两侧行号；补丁始终按文本渲染。
- `src/events.ts`：按运行 ID 和序号排序、去重、检测缺口的纯函数。
- `src/hooks/useRunEvents.ts`：唯一 SSE 连接及历史补齐生命周期。
- `src/hooks/useWorkEvents.ts`：任务清单和作业变更订阅，使当前规划、任务区与后台中心同步读取宿主状态。
- `src/config.tsx`：本浏览器下一次提交的配置覆盖；刷新恢复宿主默认。

## 实时事件怎样处理

进入详情先分页读取历史，再用最后一个连续序号订阅 SSE。收到重复序号直接忽略；发现跳号或断线时，关闭旧连接，读取持久化历史，再携带新游标重连。收到终态通知后关闭连接，并重新查询后端任务快照。

每次 effect 都有清理和独立生命周期标记，任务切换后会丢弃旧请求结果。关闭页面只停止读取，不取消后台执行；只有取消按钮会调用取消接口。轨迹默认保留最近 400 条，主动展开最多 1,000 条，后端仍保留完整记录。

执行完成、验收通过、进程清理安全是不同事实，界面分开展示。最终模型回答按受限Markdown渲染；工具输出、指令、补丁和文件预览继续按纯文本转义。局部编辑失败的后端说明直接显示在展开的执行过程与轨迹摘要中，原始参数仍按需查看；统一 LF/CRLF 的匹配和格式保持由后端文件工具完成。产物按每轮新增、修改的文件自动收集，不要求 JSON，二进制文件不能预览时仍可下载。任务表单不再填写产物路径；收集不完整由后端artifact_status/artifact_warnings单独提示，输出与历史快照仍按对应轮访问。

## 与后端的对应关系

项目保存测试命令后，可在提交表单启用“测试失败自动修复”，默认关闭、最多两次。修复与检查使用同一运行，实时展示修复次数；结果页区分当前代码的检查结果与历次检查输出。下一轮设置继承开关，也可在发送前修改；网络重试保持原请求的选择。私有独立验收不进入自动修复，重启读取历史不触发执行。

HTTP/SSE 入口位于 `src/agent_harness/web/api.py`，请求与运行视图位于同目录的 `schemas.py`；后台任务由 `service.py` 持有并复用 Runner。接口迁移不改变浏览器的 `/api` 路径。后端接入测试位于 `tests/web/`，前端行为测试继续与源码就近存放。

项目目录职责、整体阅读路线与后续阶段见 [项目概览](../PROJECT.md)。`node_modules/`、`dist/` 及本地验证输出保留原路径，在编辑器文件树中隐藏；前端源文件不受影响。

## 真实 Git 项目任务

首页通过项目选择器使用已有项目，或新建命名项目并经系统窗口绑定本机文件夹；也可由宿主 TOML 预先登记。默认直接修改所选目录，包含当前未提交改动；Git 项目在高级设置明确勾选隔离后，才从指定提交创建会话工作树。页面展示实际路径，解释器、测试命令与超时在项目设置中显式保存。

项目提交发送 `project_id`、明确的 `execution_mode` 和任务/预算，仅隔离模式附带 `base_ref`；不夹带普通 `workspace_id` 或 `verifier_id`。任务执行结束后，宿主在实际执行目录运行登记的测试命令并保存 diff；“执行”“项目测试”“人工审阅”“进程清理”分别展示。

详情检查器的“文件”页签展示基线提交、独立目录、增改删/二进制文件清单、有界纯文本补丁和完整补丁下载。任务仍活动或代码快照未就绪时不能做审阅决定。“保留工作树”仅保留独立目录与补丁，不会创建提交或合并；“丢弃工作树”需要确认，只回收本任务工作树，运行历史、测试输出与保存的补丁继续提供。已保留的工作树之后也可丢弃，丢弃后不能恢复该工作树状态。

服务重启遗留的非活动待捕获任务，进入代码页签时会读取宿主审阅接口，补捕获一次代码证据；不恢复模型执行或项目测试。

审阅请求失败时页面保留原事实，不提前更新成功状态。工作树在证据保存后又被手工修改时，宿主会拒绝过期快照的审阅操作，页面展示实际错误；刷新页面不会重做快照。工作树丢弃后，已固定的历史产物与补丁仍可下载。

默认项目列表为空，打开真实目录后即可开始任务；自定义任务的产物可以是任意格式。


## 多轮任务交互

详情采用持续会话工作区。`RunDetailPage.tsx` 以session_id固定消息区，`ConversationPanel.tsx` 展示消息与底部输入，服务确认后原地追加独立新轮；`RunInspector.tsx` 按所选轮次显示测试、上下文、轨迹与代码。代码页明确后续 diff 是相对会话原始基线的累计差异，新轮重新待审阅。

每次明确提交生成 request_id，网络失败重试沿用同一编号和载荷；sessionStorage按会话保存当前标签页草稿及未确认请求的原父轮/载荷，刷新不自动提交。运行中可以编辑、不能新提交；回看旧轮只切换检查器，发送仍追加最新轮。审阅决定与快照恢复会刷新会话可继续条件。后端对应 `web/conversations.py`、`sessions.py` 和 `snapshots.py`；完整限制见 [多轮任务交互](../docs/MULTITURN_TASKS.md)。

首轮与续轮统一通过 `/api/jobs` 接纳。其他会话占用执行槽时可以排队，同会话已有活动或排队请求时不能重复发送。新任务表单也保存未确认提交的固定载荷，刷新不重发；后台中心 `/jobs` 展示排队、执行、等待决定、待核对与检查结果。作业尚未建立 Run 时不提供运行链接。

会话内 `TasksPanel` 展示持久工作项、依赖、完成条件、证据及人工操作；`PlanningPanel` 的当前进度来自同一清单。重开前置后，下游旧证据保留但不计当前完成。历史检查器读取当轮固定快照。协议及验收见 [Agent Tasks](../docs/TASKS.md)。


`hooks/useConversationSend.ts`管理草稿与确认请求；网络不确定时“重试确认”固定原父轮和正文，即使输入已改成下一条也不改变原请求。`MarkdownMessage.tsx`使用react-markdown/remark-gfm展示回答，禁用原始HTML和危险协议，代码按用户点击复制，外部图片只显示替代文本。`TurnActivity.tsx`与activity.ts把实际工具/验收事件投影为可折叠过程，最新轮共享SSE，历史展开才读有界事件。主消息区统一纵向滚动，代码/表格可横向滚动；底部输入不随历史滚出视口，支持输入法及Enter/Shift+Enter。

上下文配置与证据：SettingsPage 只编辑模型、五类工具与模型轮次、工具次数、总时限，内部上下文、重试、输出和清理参数由宿主 TOML 维护，ContextPanel显示实际输入检查，CompressionActions展示已落盘变换及来源。聊天保持完整，摘要按纯文本展示；计数来自RunView.context，刷新不重新执行压缩。


### 中断后继续

可信中断记录沿用原会话输入框发送“继续”；页面提示使用已保存历史与当前代码，原轮保持中断，新轮独立执行、测试与审阅。正式检查器不提供独立检查点恢复按钮，刷新与读取提示不自动提交。接口可选字段continuation_notice用于非阻断提示，坏记录或来源变化仍显示具体原因。

### 项目与文件夹绑定

首页在任务输入前提供可按名称或路径搜索的项目选择器及“新建项目”。创建流程先填写名称、选择本机目录，再确认保存；同一目录直接选用已有项目。绑定路径和项目设置入口在选择器下方展示；项目设置可独立改名，所有导航和会话来源同步更新。原生选择取消不写登记，切换项目保留任务文字并重置隔离与自动修复选择。项目列表仍统一使用 `recent_projects`；选择草稿采用短期凭据，任务只发送登记ID。


项目记忆入口由 `MemoryPanel` 统一管理人工保存、候选决定、修订和导出；消息保存复用 `MemoryEditor`。运行上下文只展示固定 `MemorySnapshot`，当前候选状态另读管理 API。两个记忆选择随新任务/续轮载荷冻结，内部限额只读。type 决定动态字段和类型呈现，origin 单独记录形成方式；范围、证据与入口分开编辑，冲突必须明确选择版本化替代，逐次输入按真实事件回看，详见[记忆协议](../docs/MEMORY.md)。
