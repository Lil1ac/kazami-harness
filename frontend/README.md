# Agent Harness 控制台

React、TypeScript、Vite、Ant Design 构成浏览器界面，任务仍由 Python 后端的同一个 Runner 执行。前端不持有模型密钥，也不执行模型工具。

## 开发与检查

需要 Node.js 22.12 或更新兼容版本。Windows 下可用 `npm.cmd` 避免 PowerShell 脚本执行策略影响。

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

开发页面是 `http://127.0.0.1:5173`，`/api` 自动代理到 `127.0.0.1:8765`。Python 服务的启动命令见 [项目根 README](../README.md#启动网页控制台)，宿主配置与 HTTP/SSE 契约见 [控制台说明](../docs/WEB_CONSOLE.md)。构建后 `dist/` 由 Python 服务直接提供，普通路由刷新也由后端返回 SPA 入口。

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run format
```

`typecheck` 与 `build` 独立执行。`test` 是离线单次运行，不访问真实模型。安装时如果旧版 npm 出现 `edgesOut` 依赖解析错误，可以使用临时 npm 11：`npm.cmd exec --yes --package=npm@11 -- npm ci`，无需修改全局 npm。

## 代码从哪里读

- `src/types.ts`：对应 Python 数据模型与 HTTP 接口的类型，单位和可选字段有中文说明。
- `src/api.ts`：HTTP 请求、受控错误、产物 URL，页面不直接拼任意宿主路径。
- `src/pages/`：任务列表、详情、运行配置三个页面。
- `src/components/`：提交表单、运行状态、事件轨迹、产物、项目代码审阅和验收面板。
- `src/events.ts`：按运行 ID 和序号排序、去重、检测缺口的纯函数。
- `src/hooks/useRunEvents.ts`：唯一 SSE 连接及历史补齐生命周期。
- `src/config.tsx`：本浏览器下一次提交的配置覆盖；刷新恢复宿主默认。

## 实时事件怎样处理

进入详情先分页读取历史，再用最后一个连续序号订阅 SSE。收到重复序号直接忽略；发现跳号或断线时，关闭旧连接，读取持久化历史，再携带新游标重连。收到终态通知后关闭连接，并重新查询后端任务快照。

每次 effect 都有清理和独立生命周期标记，任务切换后会丢弃旧请求结果。关闭页面只停止读取，不取消后台执行；只有取消按钮会调用取消接口。轨迹默认保留最近 400 条，主动展开最多 1,000 条，后端仍保留完整记录。

执行完成、验收通过、进程清理安全是不同事实，界面分开展示。最终模型回答按受限Markdown渲染；工具输出、指令、补丁和文件预览继续按纯文本转义。产物不要求 JSON，二进制文件不能预览时仍可下载。

日志样例按钮只填充草稿并启用所需四类工具，不自动执行。固定日志验收器仅适用于仓库提供的日志样例。

## 与后端的对应关系

HTTP/SSE 入口位于 `src/agent_harness/web/api.py`，请求与运行视图位于同目录的 `schemas.py`；后台任务由 `service.py` 持有并复用 Runner。接口迁移不改变浏览器的 `/api` 路径。后端接入测试位于 `tests/web/`，前端行为测试继续与源码就近存放。

项目目录职责、整体阅读路线与后续阶段见 [项目概览](../PROJECT.md)。`node_modules/`、`dist/` 及本地验证输出保留原路径，在编辑器文件树中隐藏；前端源文件不受影响。

## 真实 Git 项目任务

宿主通过 Web 配置登记 Git 仓库与测试命令后，任务表单会出现“代码项目”选项。页面展示原仓库、当前 HEAD、未提交改动状态、固定测试命令与超时；可以指定提交引用，空白按 HEAD 处理。宿主从选定提交建立本任务的独立 worktree，原目录中的未提交改动不带入任务。

项目提交只发送 `project_id`、`base_ref` 和任务/预算，不夹带普通 `workspace_id` 或 `verifier_id`。任务执行结束后，宿主在独立工作树中运行登记的测试命令并保存 diff；“执行”“项目测试”“人工审阅”“进程清理”分别展示。

详情检查器的“代码”页签展示基线提交、独立目录、增改删/二进制文件清单、有界纯文本补丁和完整补丁下载。任务仍活动或代码快照未就绪时不能做审阅决定。“保留工作树”仅保留独立目录与补丁，不会创建提交或合并；“丢弃工作树”需要确认，只回收本任务工作树，运行历史、测试输出与保存的补丁继续提供。已保留的工作树之后也可丢弃，丢弃后不能恢复该工作树状态。

服务重启遗留的非活动待捕获任务，进入代码页签时会读取宿主审阅接口，补捕获一次代码证据；不恢复模型执行或项目测试。

审阅请求失败时页面保留原事实，不提前更新成功状态。工作树在证据保存后又被手工修改时，宿主会拒绝过期快照的审阅操作，页面展示实际错误；刷新页面不会重做快照。工作树丢弃后，工作区产物入口禁用，运行记录中的输出与补丁仍可下载。

未登记项目时，原普通工作区和日志样例入口保持可用；自定义任务的产物仍可以是任意格式。


## 多轮任务交互

详情采用持续会话工作区。`RunDetailPage.tsx` 以session_id固定消息区，`ConversationPanel.tsx` 展示消息与底部输入，服务确认后原地追加独立新轮；`RunInspector.tsx` 按所选轮次显示测试、上下文、轨迹与代码。代码页明确后续 diff 是相对会话原始基线的累计差异，新轮重新待审阅。

每次明确提交生成 request_id，网络失败重试沿用同一编号和载荷；sessionStorage按会话保存当前标签页草稿及未确认请求的原父轮/载荷，刷新不自动提交。运行中可以编辑、不能新提交；回看旧轮只切换检查器，发送仍追加最新轮。审阅决定与快照恢复会刷新会话可继续条件。后端对应 `web/conversations.py`、`sessions.py` 和 `snapshots.py`；完整限制见 [多轮任务交互](../docs/MULTITURN_TASKS.md)。


`hooks/useConversationSend.ts`管理草稿与确认请求；网络不确定时“重试确认”固定原父轮和正文，即使输入已改成下一条也不改变原请求。`MarkdownMessage.tsx`使用react-markdown/remark-gfm展示回答，禁用原始HTML和危险协议，代码按用户点击复制，外部图片只显示替代文本。`TurnActivity.tsx`与activity.ts把实际工具/验收事件投影为可折叠过程，最新轮共享SSE，历史展开才读有界事件。主消息区统一纵向滚动，代码/表格可横向滚动；底部输入不随历史滚出视口，支持输入法及Enter/Shift+Enter。

上下文配置与证据：SettingsPage编辑策略和预算，ContextPanel显示实际输入检查，CompressionActions展示已落盘变换及来源。聊天保持完整，摘要按纯文本展示；计数来自RunView.context，刷新不重新执行压缩。


### 中断后继续

可信中断记录沿用原会话输入框发送“继续”；页面提示使用已保存历史与当前代码，原轮保持中断，新轮独立执行、测试与审阅。正式检查器不提供独立检查点恢复按钮，刷新与读取提示不自动提交。接口可选字段continuation_notice用于非阻断提示，坏记录或来源变化仍显示具体原因。
