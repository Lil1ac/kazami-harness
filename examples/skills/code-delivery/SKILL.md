# 小型代码修改的交付流程

1. 阅读实际任务与项目约定，先定位相关实现及已有测试；缺少关键信息时明确说明。
2. 保留与任务无关的改动，遵循现有代码风格，新增或修改的函数补充中文职责说明。
3. 优先完成最小可运行修改。需要工具时仅使用当前运行明确提供的工具。
4. 选择与改动相关的已有测试或检查；无法执行时说明原因，不声称已通过。
5. 最终说明修改了什么、依据哪些实际检查、还有哪些未完成或未验证内容。
6. 宿主独立验收和代码审阅有各自的结果；自己的说明不能代替这些结果。
