# 真实项目任务与代码审阅

本功能面向本地开发者：把一个范围明确的小修改交给 Agent，在独立 Git 工作树中执行，随后检查代码 diff 和已有测试结果，再决定保留或丢弃。普通文件任务和日志样例仍可使用。

## 1. 登记已有项目

在根目录 `web.example.toml` 中增加项目预设。下面的路径需要替换为你自己的 Git 仓库根目录和已安装项目依赖的解释器：

```toml
[[projects]]
id = "my-api"
label = "我的后端项目"
path = "D:/work/my-api"
test_argv = ["D:/work/my-api/.venv/Scripts/python.exe", "-m", "pytest", "-q"]
test_timeout_seconds = 60.0
test_python_paths = ["src", "."]
```

项目和命令由宿主配置登记，页面只提交项目编号。相对路径以 TOML 所在目录解释；测试程序入口在启动预检时解析，参数中的 `{workspace}` 会替换成本次独立目录。参数使用数组，不经过 shell；Windows 脚本须通过显式解释器启动。只有项目的配置也可以不登记普通工作区。

第一版要求宿主已安装 Git、仓库已有提交，登记路径为仓库根，不支持子模块仓库。Git 操作禁用外部 clean/smudge/process 过滤器，不自动获取 LFS 大文件或执行自定义转换。程序不自动安装依赖；测试应能使用已配置环境独立运行。Python 测试通过 `test_python_paths` 显式加载工作树内代码；这些相对目录不能越界。使用可编辑安装的项目尤其需要核对导入来源，避免测试跑到原目录的代码。

## 2. 提交和执行

1. 在任务工作台选择代码项目，查看当前提交、原目录未提交状态及登记的测试命令。
2. 填写小任务，例如“修复指定测试暴露的边界条件”；基线默认为 `HEAD`，也可填有效提交或引用。
3. 提交后固定解析出的提交号，并在独立 detached worktree 执行。原目录未提交的修改和未跟踪文件不复制到任务中。
4. Agent 使用现有工具和运行预算完成一轮执行；宿主随后在任务工作树中运行已登记测试。
5. 无论执行完成、失败或取消，收尾后都尝试保存当前代码改动供审阅。页面刷新或离开不取消任务。

任务工作树用于分开代码修改，命令仍处于可信本地模式，未提供容器或进程权限沙箱。任务管理不会自动提交、回写或合并原分支。

## 3. 检查交付

运行详情的代码改动页展示基线提交、独立目录、变更文件及统一 diff。新增、修改、删除、重命名和二进制变更都登记；忽略的依赖、缓存等文件不入补丁。二进制内容通过完整 Git 补丁交付。预览有界并明确标记截断，下载的补丁不静默截断。当前上限为2000个变更文件、32MiB变更内容及32MiB完整补丁；文本预览最多256KiB。超出上限或工作树不可用时明确显示失败原因。

项目测试复用独立验收机制：正常退出 0 为通过，退出 1 为未通过，其他退出码、启动错误、取消或超时为验收异常。完整命令输出保存在运行记录中。测试通过只说明登记的检查通过，不代表自然语言需求已全部实现，也不代表用户已经接受修改；审阅时同时检查测试文件和配置是否发生变更。

执行、测试、审阅分别记录。代码快照准备期间任务仍占运行槽，页面显示“整理代码改动”；准备完成后才允许审阅操作。中断记录不自动续跑模型，服务重启仍可读取已有工作树和审阅元数据。

## 4. 保留或丢弃

- **保留工作树**：保存当前独立目录和审阅状态，可下载补丁；用户自行检查和接收修改。
- **下载补丁**：获得相对基线提交的完整修改，适用于本地审查与后续手动应用。
- **丢弃工作树**：确认后只移除该任务登记且身份匹配的工作树，运行记录与已保存补丁继续保留。

保留后仍可再次选择丢弃；已丢弃的工作树不能恢复。运行中、清理无法确认、快照未就绪、路径被替换或快照后又有非忽略的新改动时，不能直接执行丢弃。源仓库的未提交文件、索引和分支不会由这些审阅操作自动修改。模型、工具与测试受运行预算约束；工作树准备和快照另有每条Git命令30秒的上限，不承诺把这些阶段计入模型运行时长。

## 5. 实现和接口

- `projects/models.py`：宿主项目预设、文件变更与审阅模型。
- `projects/manager.py`：Git 工作树、归属核验、diff/补丁快照与审阅持久化。
- `web/service.py`：单槽提交、Runner 与项目测试组合、快照收尾和操作条件。
- `verifier.py` 与 `processes.py`：复用真实进程、输出、超时和取消处理。
- 前端：项目表单、代码改动页、测试面板及确认操作。

`GET /api/options` 增加项目列表；`POST /api/runs` 的 `project_id` 与 `workspace_id` 二选一，项目模式可传 `base_ref`，不传普通 `verifier_id`。`RunView.project` 为审阅详情，普通或旧任务为空。项目详情通过 `GET /api/runs/{id}/review` 读取；`POST /api/runs/{id}/review` 接收 `decision=keep/discard`；`GET /api/runs/{id}/diff` 提供文本预览，`GET /api/runs/{id}/patch` 下载完整补丁。

审阅元数据和补丁保存在运行根目录的 `.projects/<run_id>/`，独立于唯一写入者维护的 JSONL 执行事件；它们不伪造第二个运行终态。工作树在宿主运行目录中单独登记，原始运行和审阅证据在丢弃后仍能读取。验证结果统一见 [控制台验证记录](WEB_CONSOLE.md#7-已保留的验证证据)。
