# 工作树成果审阅、采纳与复验

本轮按2026-11-03用户批准的收窄范围实现，复用本机执行、工作树、权限、快照、持久队列与事件。保留`execution_mode`及现有执行架构；没有Docker配置、镜像、容器或执行后端预留结构。工作树分离代码，动作批准授权具体操作，均不是操作系统命令沙箱。

## 1. 使用流程

1. Agent在工作树完整收尾，固定成果。来源必须有可信终态、完整快照及已确认清理。
2. 打开“文件 → 成果采纳与历史”，选择同仓库内已登记目标。展示真实目录、仓库、当前分支或分离HEAD，不隐式切换分支。
3. 准备独立集成预览，查看相对目标的最终文件变化；此时不写目标。
4. 按路径解决文本、新增同名、修改/删除、重命名或二进制冲突。可保留目标、采用来源、编辑文本或明确删除；不支持的文件和路径形态阻止并说明原因。
5. 明确批准候选检查。正向采纳配置了测试时必须由当前候选通过检查，来源测试不能代替；没有测试允许在明确“未验收”后采纳。
6. 审阅最终目录、分支与文件清单，确认本次写回。宿主再次核对全部绑定状态，保留原索引，不自动暂存、提交或推送。
7. 单独批准目标复验。已采纳与测试通过分别记录；复验失败不自动回滚或调用修复模型。
8. 原工作树可继续开发，后续按新成果增量采纳；撤销也先准备反向候选，再审阅、确认和复验。

准备、检查、写回、撤销预览进入现有“后台工作”单槽队列，不创建虚构模型Run，不额外调用模型。页面断开不取消作业；重启只读核对，未执行队列仍需明确恢复。

## 2. 来源与目标修改

来源绑定`ProjectReview`的固定补丁摘要和`ownership.snapshot_tree`，不读取共享工作树现状补造历史。准备时批量读取基线/成果树的原始blob，保存到独立SHA256对象目录。Git对象在准备前已缺失则失败；准备完成后不再依赖来源工作树或原Git对象仍存在。

历史产物下载快照并不是成果重建机制：原`FileSnapshotStore`限制为16MiB/1000项。集成完整代码限制为256MiB/10000文件，实际写回沿用最多2000个变化文件、32MiB变化正文，超限拒绝而不截断。读取原始blob不用`git archive`，避免`export-ignore/export-subst`删改成果。

| 目标内容 | 规则 |
| --- | --- |
| 已跟踪文件 | 按实际磁盘字节参与合并；缺失文件作为删除 |
| 已暂存内容 | 固定完整索引及指纹；不修改原索引。同文件暂存版本与未暂存版本不同时，候选使用磁盘版本，原暂存版本完整保留 |
| 未暂存修改 | 进入目标快照，与来源三方合并，冲突由用户决定 |
| 非忽略未跟踪文件 | 纳入候选与检查；新增同名不能直接覆盖 |
| 忽略文件、依赖和缓存 | 不复制或自动删除；采纳路径碰撞现有忽略文件/目录时阻止。已跟踪文件即使符合忽略规则仍是源码 |
| Git/Agent控制目录、记录和受管理工作区 | 不允许写回这些位置；未修改的Agent控制文件仍可作为源码读取 |
| 未合并索引、稀疏检出、子模块、链接和特殊文件 | 首版明确阻止，不当作普通文件处理 |

文本三方合并统一UTF-8 BOM与LF/CRLF，写回已有文本时保持目标原有统一换行和BOM。非UTF-8或含NUL按二进制处理。Windows设备路径、大小写碰撞、文件/目录替换等无法可靠表达时停止；不递归删除用户目录。

## 3. 三方合并与增量

B为集成基线，R为本次固定来源成果，T为目标当前源码。在私有Git仓库用`merge-tree --merge-base`计算候选，不更新目标HEAD/索引，不创建提交。辅助Git禁用用户/系统配置、Hooks及外部驱动，不继承Electron私有标准输入。候选使用独立Git控制目录，不能向上发现目标仓库；首版不复制完整Git历史。

首次B使用会话原始基线。后续向同一目标采纳，B使用上次完整采纳的**来源成果**，不使用上次目标合并结果，避免反复带入目标已有改动。

增量流按来源会话、仓库身份、目标目录身份/路径和分支分别保存。多个目标各自维护锚点；换分支或替换目录不继承其他流。HEAD前进使旧预览失效。相同来源在该流已采纳时返回“该成果已采纳”，较旧轮次不能隐式倒退；目标后续人工修改不触发旧成果重放。

完整写回并保存回执后，采纳事实与锚点同一SQLite事务发布。目标复验失败不倒退已发生的写回事实；部分写入、中断或结果不明不推进锚点。

## 4. 状态、权限与存储

复用`ProjectWorkspace/ProjectReview`、`WorkStore`、`PermissionStore`与`ExecutionLease`。新增`integrations`保存来源、目标、版本、固定内容、冲突、检查及采纳事实；`integration_anchors`保存各流最近已采纳来源。没有第二套队列。

- `revision/fingerprint`绑定来源树与补丁摘要、目标目录/分支/HEAD/索引/源码、解决结果、最终变化和测试配置；旧确认不能批准新内容。
- `preparing/conflicts/ready`表示准备与解决；目标变化进入`stale`。
- `applying/applied`表示写回事实；不完整进入`needs_review`。
- 原记录`undone`表示已受保护撤销；`abandoned`表示用户明确保留现场、放弃原操作，不等于目标已恢复。
- `jobs.kind=integration`复用原单槽队列，`run_id`仅链接来源，`integration_id`标识实际成果作业；后台中心进入对应文件页。

人工按钮批准具体检查或固定写回，模型没有批准或采纳工具。宿主read/write/verification禁止及目录上限不能绕过；完整准备需要允许读取项目根。许可、策略指纹、有效期和入队同事务保存；同内容重试保留请求编号，取消排队撤销未消费许可。纯人工集成不重置模型Run预算，不自动调用模型。

固定对象、索引备份、逐文件日志、检查原始输出位于受保护记录根`.integrations/<id>`；临时检查目录位于现有`worktrees_root/.integrations/<id>`，与来源、目标和证据目录分别归属。

## 5. 写回与恢复

写入前所有前值已按摘要备份。逐文件先持久保存`intent`，再同目录临时文件替换或删除，最后保存`written`。每个文件边界核对目录、分支、HEAD、索引及本文件前值。全部完成后核对完整目标，先落盘完整文件回执，再发布SQLite事实。

| 故障 | 行为 |
| --- | --- |
| 准备后目标、配置或权限变化 | 原确认失效，重新准备与审阅 |
| 排队取消、批准过期 | 未消费动作不执行，目标保留 |
| 写文件前停止、无intent | 可确认尚未写文件，记录取消/失败 |
| 部分写回、intent后中断或缺回执 | 保留现场和备份，暂停队列，不自动重放或盲目回滚 |
| 完整文件回执已落盘、SQLite发布失败 | 启动补记可信事实及锚点，不重写目标 |
| 无完整回执、现场全为预期后值 | 先显示逐文件观察；用户明确确认后再次核对完整代码与索引，保存人工对账回执 |
| 现场含前值或外部版本 | 不确认成功；用户可核对后放弃原操作，保留现场并重新准备剩余集成 |
| 准备或检查进程失联 | 后台中心明确确认进程停止，再解除阻塞；此前“已采纳”不等于本次检查完成，旧请求不重放 |

同数据目录使用现有执行锁与队列串行化，不约束外部编辑器、其他程序或未协调的数据目录实例。文件系统与SQLite不是跨存储原子事务，不宣称任意副作用恰好执行一次。

写回中断的`recovery_kind=files`只能进入逐文件核对；准备/检查中断的`process`提供进程停止确认。确认清理未知的检查后恢复可检查状态，旧结论不适用，原采纳事实与增量锚点保持。中断准备记录明确失败，不留永久“准备中”。

## 6. 检查、撤销与继续开发

三类检查分别记录，保留命令、cwd、解释器、源码版本、输出及清理事实：

1. 来源检查增加`code_before/code_after`的Git规范源码指纹。只有与固定成果一致才标适用；缺少可核验证据时只保留原运行事实，不补造通过。
2. 候选检查固定源码导入到独立目录，可复用目标已配置的解释器和依赖，不复制`.venv`或忽略凭据。命令直接引用目标绝对脚本路径时拒绝，要求使用相对路径重新准备。依赖/Git历史不满足时明确失败，不静默改测目标。
3. 采纳后目标复验核对实际源码；前后源码变化、目标分支或索引变化使结论不适用。通过、失败、异常、取消和未配置均保留真实事实。检查进程清理未知时，即使退出码通过，结论仍不可用于批准采纳。

正向候选失败/异常时先修复来源或解决结果再准备；没有测试可明确未验收后采纳。目标复验失败保持“已采纳、检查失败”，不自动修改或回滚。目标后续开发的代码不由旧检查证明，需使用新运行或新集成记录验收。

撤销只撤回本次M−T，恢复采纳前目标字节，保留当时已有修改。首版只允许撤销目标最近一条仍有效的正向采纳；HEAD、分支、索引及涉及文件必须仍满足保护条件。后续编辑、暂存或提交改变这些条件则拒绝，不提供强制覆盖。先生成反向候选再确认；它可能恢复原有失败代码，界面明确提示，允许撤销后复验。完整撤销才恢复上一来源锚点，其他目标不受影响。

原工作树可以继续执行，下一轮成果重新固定；原有保留/丢弃职责不变。活动或待核对集成作业阻止同时处理来源共享工作树。续轮、撤销不删除历史补丁、来源产物、检查和备份。只有用户明确彻底删除会话时才清理关联集成历史、候选、许可与备份，并说明此后不能借记录撤销；项目代码和另存记忆保留。

## 7. HTTP与边界

- `GET /api/runs/{id}/integration-targets`：登记目标。
- `POST /api/runs/{id}/integrations`：request_id/target_id接纳准备。
- `GET /api/runs/{id}/integrations`：来源会话历史。
- `GET /api/integrations/{id}`：固定事实和最近作业。
- `GET /api/integrations/{id}/file?path=...`：有界纯文本三方内容与最终差异。
- `POST /api/integrations/{id}/resolutions`：版本化逐路径解决。
- `POST /api/integrations/{id}/actions`：候选检查、确认写回、目标复验、撤销预览、核对或放弃。
- `GET /api/integrations/{id}/checks/{check_id}/artifacts?path=...`：仅下载该次检查已登记的原始标准输出/错误；桌面同样经过认证和受控原生下载，不接受任意文件路径。

桌面和Web共用接口、同源/桌面认证、类型和交互。本轮没有新增CLI采纳命令，CLI既有执行/查看行为保留。

本机测试仍具有系统用户的命令访问能力，独立候选目录不能保证任意脚本无法通过绝对路径修改其他目录。流程不主动在确认前写目标，并在边界核对变化；不称为操作系统沙箱。Windows原生沙箱后续独立评估成熟实现复用、兼容、分发和维护成本；Docker保留为固定Linux环境/批量回归实际需求触发的可选方向。
