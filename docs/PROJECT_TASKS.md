# 真实项目任务与代码审阅

当前默认直接修改打开的原目录，包含现有未提交文件，续轮仍使用该目录；每轮保存相对开始时的差异和固定产物。下面的 detached worktree、固定提交与保留/丢弃规则只适用于明确选择“隔离执行”的会话。原目录使用相同项目测试配置，但不创建 ProjectReview，不自动暂存/提交或应用/丢弃代码。详见 [本机项目执行方式](LOCAL_PROJECTS.md#原目录执行与逐轮证据)。


本功能面向本地开发者：把一个范围明确的小修改交给 Agent，在独立 Git 工作树中执行，随后检查代码 diff 和已有测试结果，再决定保留或丢弃。普通文件任务和日志样例仍可使用。

## 1. 打开已有项目

首页点击“选择项目文件夹”，在 Windows 系统窗口中选择 Git 仓库根目录。页面显示真实路径、分支、当前提交和未提交状态，并保存到最近项目。下次可直接重新打开，首次使用不需要修改 TOML；取消选择不会登记目录或启动任务。无提交仓库可以登记但暂不能执行，Git 子目录与裸仓库明确拒绝。普通文件夹也可打开，始终使用所选目录，不提供副本模式；详细范围见 [打开本机项目](LOCAL_PROJECTS.md)。

项目测试可在项目页“项目设置”中填写并显式保存，例如输入已有解释器的绝对路径与 pytest 参数。保存只检查程序入口和参数格式，不执行测试；留空并保存可清空。未配置测试仍可执行代码任务，验收状态保持 unverified。依赖需要事先安装，系统不自动安装。

保存测试后可勾选“测试失败自动修复（最多2次）”。默认关闭；开启后只有公开项目测试正常断言失败才回传有界反馈，在同一任务和剩余预算内修复、重测。测试异常或取消立即停止。概况保留当前代码检查及所有历史失败和输出，最终差异/产物对应最后代码；任务完成后下一轮可继承、更改开关，旧轮不受影响。独立验收不参与反馈。

也可在 `web.example.toml` 中登记初始项目。下面的路径需要替换为你自己的 Git 仓库根目录和已安装项目依赖的解释器：

```toml
[[projects]]
id = "my-api"
label = "我的后端项目"
path = "D:/work/my-api"
test_argv = ["D:/work/my-api/.venv/Scripts/python.exe", "-m", "pytest", "-q"]
test_timeout_seconds = 60.0
python_paths = ["src", "."]
```

TOML 作为可选初始登记，与页面打开的目录合并；任务接口仍只提交项目编号。TOML 相对路径以该文件所在目录解释，页面保存的相对测试程序路径以项目根目录解释；测试入口固定为绝对程序。参数中的 `{workspace}` 会替换成本次独立目录。命令分词后使用参数数组，不经过 shell；Windows 脚本须通过显式解释器启动，不能直接把 npm.cmd 当作程序入口。只有项目的配置也可以不登记普通工作区。

代码任务要求宿主已安装 Git、仓库已有提交，打开路径为仓库根，不支持子模块仓库。Git 操作禁用外部 clean/smudge/process 过滤器，不自动获取 LFS 大文件或执行自定义转换。程序不自动安装依赖；测试应能使用已配置环境独立运行。Python 测试通过 `python_paths` 显式加载工作树内代码；这些相对目录不能越界。使用可编辑安装的项目尤其需要核对导入来源，避免测试跑到原目录的代码。

## 2. 提交和执行

1. 在首页打开代码项目或最近项目，查看实际路径、分支、当前提交、原目录未提交状态及可选测试命令。
2. 填写小任务，例如“修复指定测试暴露的边界条件”；基线默认为 `HEAD`，也可填有效提交或引用。
3. 提交后固定解析出的提交号，并在独立 detached worktree 执行。原目录未提交的修改和未跟踪文件不复制到任务中。
4. Agent 使用现有工具和运行预算完成一轮执行；已配置测试时，宿主随后在任务工作树中运行检查，未配置保持未验收。
5. 无论执行完成、失败或取消，收尾后都尝试保存当前代码改动供审阅。页面刷新或离开不取消任务。

任务工作树用于分开代码修改，命令仍处于可信本地模式，未提供容器或进程权限沙箱。任务管理不会自动提交、回写或合并原分支。

## 3. 检查交付

运行详情的代码改动页展示基线提交、独立目录、变更文件及统一 diff。新增、修改、删除、重命名和二进制变更都登记；忽略的依赖、缓存等文件不入补丁。二进制内容通过完整 Git 补丁交付。预览有界并明确标记截断，下载的补丁不静默截断。当前上限为2000个变更文件、32MiB变更内容及32MiB完整补丁；文本预览最多256KiB。超出上限或工作树不可用时明确显示失败原因。

项目测试为可选项，未配置时不执行验收且保持 unverified。已配置测试复用独立验收机制：正常退出 0 为通过，退出 1 为未通过，其他退出码、启动错误、取消或超时为验收异常。完整命令输出保存在运行记录中。测试通过只说明登记的检查通过，不代表自然语言需求已全部实现，也不代表用户已经接受修改；审阅时同时检查测试文件和配置是否发生变更。

执行、测试、审阅分别记录。代码快照准备期间任务仍占运行槽，页面显示“整理交付文件”；准备完成后才允许审阅操作。中断记录不自动续跑模型，服务重启仍可读取已有工作树和审阅元数据。

## 4. 保留或丢弃

- **保留工作树**：保存当前独立目录和审阅状态，可下载补丁；用户自行检查和接收修改。
- **下载补丁**：获得相对基线提交的完整修改，适用于本地审查与后续手动应用。
- **丢弃工作树**：仅最新轮可确认移除该会话登记且身份匹配的工作树，运行记录、历史文件快照和补丁继续保留。

保留后仍可再次选择丢弃；已丢弃的工作树不能恢复。运行中、清理无法确认、快照未就绪、路径被替换或快照后又有非忽略的新改动时，不能直接执行丢弃。源仓库的未提交文件、索引和分支不会由这些审阅操作自动修改。模型、工具与测试受运行预算约束；工作树准备和快照另有每条Git命令30秒的上限，不承诺把这些阶段计入模型运行时长。

## 5. 实现和接口

- `projects/models.py`：宿主项目预设、文件变更与审阅模型。
- `projects/manager.py`：Git 工作树、归属核验、diff/补丁快照与审阅持久化。
- `web/project_catalog.py`：本机目录登记、初始配置合并、最近项目持久化与测试设置。
- `web/folder_picker.py` 与 `web/native_dialog.py`：异步协调 Windows 系统目录选择窗口。
- `web/service.py`：单槽提交、Runner与可选项目测试组合、收尾保护和审阅操作条件；正常快照由Runner在唯一终态前固化。
- `verifier.py` 与 `processes.py`：复用真实进程、输出、超时和取消处理。
- 前端：项目表单、代码改动页、测试面板及确认操作。

`GET /api/options` 返回初始项目、最近项目及选择器能力；目录选择、重新打开和测试设置见 [本机项目协议](LOCAL_PROJECTS.md#4-http-契约)。`POST /api/runs` 的 `project_id` 与 `workspace_id` 二选一，Git隔离模式可传 `base_ref`，不传普通 `verifier_id`。`RunView.project` 为隔离Git审阅；原目录的 `execution_mode/source_path/source_kind/local_changes` 分别提供执行方式、来源、类型与本轮变化。项目详情通过 `GET /api/runs/{id}/review` 读取；`POST /api/runs/{id}/review` 接收 `decision=keep/discard`；`GET /api/runs/{id}/diff` 提供文本预览，`GET /api/runs/{id}/patch` 下载完整补丁。

审阅元数据和补丁保存在运行根目录的 `.projects/<run_id>/`，独立于唯一写入者维护的 JSONL 执行事件；它们不伪造第二个运行终态。工作树在宿主运行目录中单独登记，原始运行和审阅证据在丢弃后仍能读取。验证结果统一见 [控制台验证记录](WEB_CONSOLE.md#7-已保留的验证证据)。


## 6. 继续多轮修改

任务结束并完成代码快照后，在详情底部输入消息追加要求。每条要求产生新的运行编号；各轮在同一会话的详情检查器中查看，发送始终追加到最新轮，首版只允许线性追加。产品语义及验收见 [PRD 4.3](PRD.md#43-多轮任务交互的交付范围v02)，完整实现见 [多轮任务交互](MULTITURN_TASKS.md)。

首次 Git 隔离运行从指定提交建立会话工作树；后续 prepare_turn 只新增本轮证据并复用目录，不创建工作树或应用旧补丁。两轮间手动修改保留，各轮配置、预算、工具轨迹、项目测试、固定产物和相对会话基线的累计补丁分别留存；旧轮证据不重新捕获。产物列表只列本轮开始至结束新增、修改的文件；它与相对会话基线的累计Git补丁含义不同。

只有最新轮可保留或丢弃共享工作树，旧轮只读，运行中拒绝删除。前轮 kept 不代表新轮已经接受；丢弃后不能继续，但已保存历史文件和补丁仍可下载。不自动提交或合并。新轮尚未启动时准备失败，仅回退会话管理状态，已有目录保持。 前序记录、清理状态及目录归属必须可核对，可信中断前缀可普通消息接续，不重放未知工具。

项目 python_executable 为显式解释器，空白按 PATH 查找；模型命令和项目验收的裸 python/python3 共用当轮选择，明确程序路径及 uv 等其他入口原样执行。相对路径按实际工作区解释，不自动创建环境或安装依赖。 python_paths 继续固定当轮源码范围，省略自动根/src，[] 仅根目录。见 [Python 源码导入](PYTHON_EXECUTION.md)。

RunView.project 为该轮固定代码证据；RunView.project_workspace 为会话目录当前状态和 latest_run_id。目录归属保存在 .projects/<session_id>/workspace.json，各轮补丁及元数据在 .projects/<run_id>/，文件产物在 .project-files/<run_id>/。旧轮管理请求受控拒绝。
