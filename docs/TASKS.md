# Agent Tasks 与单机后台队列

本轮按用户批准的 C04＋C06 单机排队 Plan 实现。参考 Claude Code 的四个任务工具、持久清单与依赖机制；现有 Runner 继续执行模型和工具，队列调度 Run，工作项与 Run 为多对多关联。领域语言见 [CONTEXT](../CONTEXT.md)。

## 数据和职责

受保护的 `<runs_root>/.work/work.sqlite3` 保存任务清单、幂等操作、差量变更事件及作业。数据库事务保证任务图、版本、回执与事件一起提交。任务事件保留每个变更项的完整字段；模型工具和人工接口共用 TaskService。RunStore 仍是实际工具调用、检查和产物的事实源。

每个会话默认一个任务清单。工作项保存稳定 UUID、短编号、标题、范围、完成条件、父任务、依赖、状态、负责人、当前 Run、来源方案、版本、完成说明、证据及推进过的运行。最多五百项；工具列表最多五十项一页，概览最多二十项且进行中优先，完整内容通过 task_get 回读。

四个工具是 task_create、task_get、task_list、task_update。模型写操作的稳定编号由宿主根据 run_id 与已落盘 tool_started 序号生成，不向模型开放 request_id；网页写操作携带稳定 request_id。更新都须 expected_revision；版本冲突返回当前任务版本。模型不能指定其他会话或伪造人工批准。规划只读阶段只允许查询工作项。

状态为 pending、in_progress、completed、cancelled；阻塞由宿主计算。依赖和父子汇总共同校验无环；父任务不直接执行，进度由子项汇总。被取消父任务的子项不能开工。重新打开前置或改变条件会让下游待复核，旧说明和证据保留。父任务也不能绕过子项待复核状态；当前完成数量不计入已失效的旧完成事实。

模型完成任务前须由当前 Run 认领，提供非空完成说明，复制本轮成功工具回执中的 evidence_ref；宿主核验其指向已落盘的成功文件/命令等工具结果；任务管理工具自身不能作为完成证据。人工确认使用独立 evidence kind，不制造检查通过。Run 失败或中断保留完成项，未完成项在明确接续时重新核对。任务状态与 validation_status 始终分开。

## 与规划及上下文联动

步骤由宿主生成稳定编号。批准后按方案版本和步骤编号幂等导入任务，默认顺序依赖；不产生额外模型调用。已批准步骤正文不能由任务编辑改写，范围变化需提交新版方案。

移除 update_plan 独立进度工具。PlanStep.status 是关联任务的只读投影；历史运行在结束时固定完整清单及规划投影。旧轮 Markdown 导出继续绑定 run_id/version，不回查最新任务状态。

每次模型执行请求注入最新任务概览和当前 Run 编号；任务创建/更新的成功回执保留配对与编号，供下一轮确认执行反馈；历史按普通工具批次参与有预算的压缩，不再被规划投影无条件移除。失败结果和显式读取保留，原始磁盘轨迹完整。工具定义、概览和回读均计入既有硬预算，不增加额度。

## 作业接纳和运行

统一提交入口为 POST /api/jobs。首轮请求包含 request_id/create，续轮包含 request_id/parent_run_id/followup；外层与续轮 request_id 必须相同。旧 POST /api/runs 和 followups 提交入口移除，Run 的读取、SSE、取消及下载接口继续保留。

作业返回稳定 id、预分配 run_id、会话/项目归属、状态、结束信息及检查结果。queued/preparing 尚不能打开 Run。队列最多一百个未结束请求，先到先执行；同会话最多一个未处理作业。同一数据目录的 Runner 用操作系统文件锁排他执行，包括 CLI。

接纳时固定公开配置、目录身份、请求和父轮；隔离模式将基线解析成固定提交。排队不调用模型、不创建工作树、不运行项目命令，不消耗执行时限。出队再次检查目录、父轮、规划权限和宿主登记。模型凭据仅在执行时从宿主读取，不写作业数据。

取消 queued 不创建 Run；活动取消复用真实进程清理，证据收尾后才释放槽。等待用户决定的 Run 释放槽，回答或批准通过新作业接续。结束后不会因为清单仍有待办而无限自动新建 Run。

## 故障及界面边界

离开页面不取消服务内任务。桌面退出先停止出队，再取消活动 Run 并等待清理；未执行项保存。重启后队列暂停，已有可信运行终态可核对入账，结果不明项标 needs_review。用户确认进程已停止、工作区已核对后解除该项阻塞；恢复按钮只启动尚未执行请求，不重放原工具。

后台中心提供项目筛选、状态、停止、待核对确认及会话入口。会话内任务区提供条件、阻塞原因、关联运行、人工管理与版本冲突反馈；执行中限制结构修改。历史检查器只显示当轮任务快照。桌面与手机使用同一组件。

事务事件通过 GET /api/work-events 分页补读，也可通过 /api/work-stream 以 SSE 观察；读取不触发调度。

本轮仍是本机单用户、单执行槽。后台命令句柄、自动故障恢复、跨会话共享、Subagents、Teams 与分布式调度保留后续范围。外部编辑器及其他数据目录不属于本轮执行锁保证。

## Permission 联动（2026-11-02）

具体动作等待仍结束当前Run并释放槽位，决定通过统一作业入口提交。动作决定与接续作业在同一SQLite事务保存；排队取消同时撤销尚未消费的许可。当前动作过期、参数或宿主配置变化时，出队不执行旧操作；没有可信执行结果时进入待核对，不重放。

纯动作审批接续沿用剩余模型、工具、活动时间与修复次数，区别于普通新要求及规划决定接续的独立预算。原动作在请求时已计工具次数，批准后不重复计数。等待作业关联当前审批状态，后台中心不会一直把已处理决定显示成尚待批准；原Run的历史等待快照保持不变。协议及新增验收见[权限控制](PERMISSIONS.md)。
