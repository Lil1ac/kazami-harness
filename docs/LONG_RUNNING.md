## 命令生命周期

`run_command` 增加 `background`，默认 `false` 等待完成；`true` 返回已接纳命令句柄。两种模式均由 `execution/commands.py` 管理，实际启动、双流捕获、超时和清理由原 `ProcessRunner` 完成。宿主原参数审批包含 `background`；后台方式不能绕过规划只读、命令权限、解释器或目录范围。

- `read_command`：读取当前 Run 的状态与双流分页；只接受命令编号，不接受任意路径。
- `wait_command`：等待既有命令，不再次启动程序，也不为等待循环请求模型。
- `stop_command`：幂等停止并等待真实进程树清理；不回滚已有外部副作用。

命令以 Run、实际成员、请求轮号、调用编号和 UUID 固定归属。`command_snapshot` 依次记录启动、运行、停止与终态；重启缺终态时只读投影为 `needs_review`。PID 只作现场说明，不能用历史 PID 对新宿主发起停止。

输出按原始字节分页；双流使用独立游标。活动输出末尾不足一个 UTF-8 字符的字节留待下一页，非 UTF-8 字节用替换字符展示，游标仍按原字节计算。页面只保留有界文字窗口，原输出继续受捕获总上限约束。

同一实际工作区存在活动命令时，拒绝其他文件写入、新命令、依赖该目录的委派和计划切换。不同隔离工作树仍按原归属执行。命令结束通知必须回到模型决策；运行退出、独立检查或成果快照前，所有所属命令均须等待或清理。清理未知时不释放目录的后续写入依据。

启动成功只证明“已接纳”，不能作为命令完成证据。任务清单和开发报告均排除后台接纳及输出观察回执；实际结束回执可作命令证据，但不替代宿主独立验收。

## 输入与暂停

原 SQLite 增加 `runtime_controls`，与会话生命周期和队列共用事务。每个 Run 收件箱最多 100 条、合计 256 KiB 正文，单条最多 16000 字符。请求编号同时固定正文和投递意图，相同编号异文拒绝。

本轮补充在模型请求前和工具之间交付。收到影响旧决策的新输入后，同批尚未执行的工具全部配齐“需重新决策”的未执行回执，再把补充交回模型。输入状态区分 `received`、`delivered`、`processed`；只有实际模型响应落盘后才确认处理。主、子消费者分别记录，子项处理不冒充主 Agent 已处理。没有消费者读取且没有派发意图的输入可以撤回。

下一轮要求先持久接收，在本轮可信正常完成且清理安全后，经原队列接纳。原父编号和作业编号先固定，再等待异步响应，避免派发中撤回或响应丢失造成重复执行。遇到审批、暂停、失败或未知清理时，不自动跨过等待；页面保留消息和原因，由用户明确处理。重启本身不会补发消息或自动启动 Run。

暂停请求只发布 `pausing`。Runner 在安全边界停止新增动作，等待命令和子执行结束、固定证据后，才发布 `paused` 与 `execution_checkpoint`。需要立即终止时使用原停止入口或单条命令停止；暂停不声称冻结操作系统进程。

恢复必须通过明确的 `resume=true` 续轮请求，不能夹带配置、权限或审批决定。宿主验证最新父段、安全清理及目录身份后创建新段。此前模型轮次、工具次数、活动秒数、已知 token、修复次数及委派约束都沿用；安全暂停后的人类等待不消耗活动时限，也不增加额度。新段以当前代码建立基线，先核对历史和现场，不自动重放旧工具。

暂停前尚未处理的补充继续进入新段收件箱；已安全停止的子执行沿用原工作树或只读工作区、可信历史和各自剩余预算接续。团队成员身份、原任务和依赖依据继续核验。已有子审批优先保留原审批链，不能改用暂停恢复绕过批准。

## 接口与页面

| 接口 | 行为 |
| --- | --- |
| `GET /api/runs/{run_id}/runtime` | 本段控制状态、消息及直属子命令，只读历史 |
| `POST /api/runs/{run_id}/inputs` | 幂等接纳本轮补充或下一轮要求 |
| `DELETE /api/runs/{run_id}/inputs/{message_id}` | 撤回尚未交付的输入 |
| `POST /api/runs/{run_id}/pause` | 请求安全暂停，不直接发布已暂停 |
| `GET /api/runs/{run_id}/commands/{command_id}/output` | 按所属主/子段与双流游标读取输出 |
| `POST /api/runs/{run_id}/commands/{command_id}/stop` | 仅停止当前宿主持有的所属命令 |
| `POST /api/runs/{run_id}/dispatch-next` | 明确核对并投递原下一轮意图 |
| 原 `POST /api/jobs` + `followup.resume=true` | 沿用原队列恢复安全暂停 |

归档、回收站、历史及删除访问限制沿用原会话边界。彻底删除会话时同步删除收件箱正文和控制状态。历史 Run 事件、命令及产物不会因新段接续而修改；历史页面没有停止进程或管理旧输入的入口。

会话输入区支持本轮补充、下一轮执行、暂停、停止和恢复；逐轮展示接纳与处理状态。命令展开后才读取输出，保留真实目录、退出码与清理风险。后台中心可查看活动命令并进入对应会话。桌面彻底退出仍按原规则安全收尾，不承诺关闭桌面后常驻。
