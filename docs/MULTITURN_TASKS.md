# 多轮任务交互

V0.2 首版已交付，产品范围与 M01—M06 见 [PRD 4.3](PRD.md#43-多轮任务交互的交付范围v02)。本文件维护当前架构、追加规则和接口；实际验证证据集中于 [控制台说明](WEB_CONSOLE.md#7-已保留的验证证据)。历史压缩与中断后普通消息接续已接入；一条用户消息对应一个独立运行，运行中插话和并行分支暂缓。

## 1. 使用流程

1. 在工作台提交普通文件或代码项目任务，等待执行、验收及快照收尾。
2. 在会话消息区查看要求和回答，在底部“输入消息”填写下一条要求，点击“发送”或按Enter。
3. 服务核对前轮记录与代码状态，建立新的运行和独立工作区；原地补入新轮，更新路由但保留同一会话消息区和输入节点。
4. 新轮单独使用预算、调用工具、保存事件；正常完成执行后重新运行宿主登记的验收。代码项目重新等待审阅，可进入“代码改动”查看本轮交付。
5. 点击各轮“本轮详情”回看旧测试、上下文、产物与补丁。检查器可选旧轮，输入仍明确追加到最新轮，查看历史不产生分支。

运行中允许编辑追加输入，但禁止提交；页面说明等待或取消的原因。失败保留输入。刷新、关闭页面或重新启动服务只恢复读取，不自动提交要求或执行旧工具。

## 2. 会话与执行的关系

```text
同一会话（session_id 等于首轮 run_id）
  第1轮 Run A → 第2轮 Run B → 第3轮 Run C
                parent=A      parent=B
```

每条接纳的用户要求对应独立 Run；Run 内部仍可进行多轮模型/工具调用。`turn_index` 从1开始表示用户轮次，`result.model_turns` 表示该次执行的实际模型轮次，两者含义不同。

`RunManifest` 保存以下可兼容字段，旧记录不需要改写：

| 字段 | 含义 |
| --- | --- |
| session_id | 会话首轮编号；旧记录为空时按自身 run_id 展示 |
| parent_run_id | 直接前轮编号；首轮为空 |
| turn_index | 用户要求的顺序，首轮默认1 |
| origin | 宿主登记的项目/工作区编号与固定路径；普通任务还固定验收器编号 |
| history_source | 后续运行使用的前轮事件最大序号与消息 SHA-256；首轮为空 |

配置和预期产物默认沿用前轮；API 可覆盖已有开放配置，页面沿用本浏览器的公开配置草稿。宿主系统提示重新生成，工作区与验收来源不能通过追加请求任意切换。每轮实际计数从零开始，旧配置和结果保持不变。

## 3. 历史如何继承

`sessions.history_messages` 默认只读取可信终态直接前轮；宿主显式接纳中断来源时，另核对完整事件前缀，为尾部缺失结果补充未知或未开始标记。原日志不改写。前轮初始消息已经包含更早历史，因此不递归重复拼接。保留用户要求、回答、reasoning_content、工具调用及配对结果，去掉旧宿主规则和旧项目指令前缀；配对不完整或记录受损时拒绝继续。

新轮的 `ContextBuilder` 重新加载当前工作区根 AGENTS.md，将当前宿主规则、当前项目指令、继承历史和新要求组成完整输入。历史中的旧目录和旧测试仅作为前轮证据，新轮必须在当前工作区执行并重新验收。模型调用前再次核对前轮事件序号与历史摘要，并记录 `history_loaded`。

完整历史与工具定义继续计入 UTF-8 JSON 输入预算；压缩使用有来源的投影，原始记录保留，不静默截断。超限时本轮 `limit_exceeded`，未实际发出的请求不增加模型/HTTP计数；旧文件、记录与补丁仍保留。预算和计量规则见 [上下文管理](CONTEXT_MANAGEMENT.md)。

## 4. 代码和文件如何继承

### Git 项目

`ProjectManager.prepare_followup` 核对前轮工作树归属、Git 注册、保存补丁完整性及当前树摘要，然后从会话初始提交创建新 worktree，应用前轮完整累计二进制补丁。应用后再次核对新树与前轮，成功后才启动 Runner。应用时固定本次 Git 命令的换行转换行为，避免 Windows 自动转换导致内容偏离快照；不修改用户 Git 配置。

每轮有自己的工作树、测试输出、代码快照、完整补丁和审阅状态。新轮审阅为 pending，前轮 kept 不会自动接受新改动；原仓库和前轮工作树不由继承动作改写。每轮 diff 均相对会话初始提交，表示累计交付差异；当前不提供只比较前后两轮的增量 diff。已丢弃或快照后被手动改动的最新工作树不能直接继续。

### 普通工作区

`FileSnapshotStore` 在运行收尾保存完整文件树，最多 **1000个目录项、16MiB文件正文**。清单保存来源目录身份、相对路径、大小、SHA-256及普通权限，包含二进制文件和空目录；拒绝链接、Git 控制目录及特殊文件。保存失败只记录不能继续的原因，不把已经完成的执行改成失败。

追加时先核对当前来源目录身份与内容，再从保存副本建立新 UUID 目录，并核对副本和来源。来源被替换或修改、快照损坏、超过上限时，在调用模型前拒绝。普通首轮仍遵循原来的 copy_on_run 配置；后续轮始终派生独立副本。

这些快照用于核验和继承，历史产物下载仍通过原登记路径访问；本次没有改变产物下载语义。普通模式中的大型目录或 Git 仓库无法保存可继续快照，应选择代码项目模式或缩小登记工作区。

## 5. 请求幂等与服务重启

`ConversationService` 在现有 WebRunManager 的全局单槽内准备和启动新轮，执行仍交给唯一 Runner。`SessionStore` 在受保护记录目录 `.sessions/<session_id>.json` 中原子保存线性关系与请求意图；普通文件快照存放于 `.file-snapshots/<run_id>/`，Git证据仍位于 `.projects/<run_id>/`。这些元数据不成为第二个 JSONL 写入者。

请求以会话内唯一 `request_id` 和完整载荷摘要识别：

| 状态 | 行为 |
| --- | --- |
| preparing | 准备工作区前落盘；同进程重复请求等待同一准备任务 |
| committed | 准备完成后先固定新轮关系，再启动一次 Runner；重复请求返回原运行 |
| failed | 准备失败不推进会话最新轮；同编号重试返回原失败原因 |
| 编号相同但载荷不同 | 返回 request_conflict，不执行新动作 |
| 重启后准备状态不确定或已登记但缺少运行 | 明确说明待核对，不自动再次准备或执行 |

HTTP请求断开不取消后台准备。前端在 sessionStorage 按会话保存当前标签页未发送草稿及未确认请求的原父轮、编号、正文和公开配置，并兼容旧逐运行存储键；网络失败后用户“重试确认”沿用原载荷。发送期间编辑的不同新草稿继续保留。刷新只恢复输入和确认入口，不自动发送。确定未接纳的校验失败允许用户核对后新提交；未知结果不能通过换编号自动重试。

服务重启后可读完整会话，并从可核对的最新终态明确发起新要求。服务中断后可打开原会话并发送“继续”；新请求继承可核对记录与当前代码，宿主不自动重放旧工具。

## 6. HTTP 与页面契约

`GET /api/runs/{id}/conversation` 返回 `session_id`、`latest_run_id`、有序 `turns`、`can_continue`、可空 `blocked_code/blocked_reason` 和 `busy_run_id`。各轮提供运行关系、用户要求、最终回答、执行/验收状态及可空创建时间。读取不会重新执行或重新捕获代码；GET给出静态可用条件，实际内容核验仍在提交准备时进行。

`POST /api/runs/{id}/followups` 只允许从最新轮追加：

```json
{
  "request_id": "c1f54d17-b15c-4674-aac6-62311d6420f6",
  "prompt": "保留上次修复，再补充参数类型和中文说明。",
  "config": {"limits": {"max_model_turns": 12}},
  "expected_outputs": null
}
```

`request_id` 为 UUID；`prompt` 为1至65536字符，空白要求被拒绝。`config` 可省略，复用现有受限覆盖字段；`expected_outputs` 缺省或 null 沿用前轮，空列表表示不声明预期产物。不能传入新宿主路径、项目、基线、验收 argv 或凭据。

成功202返回新/原 `RunView`，其中包含会话、前轮和用户轮次。忙碌、旧轮追加、工作区变化、已丢弃和不确定请求返回409及受控原因；请求结构错误沿用422，运行不存在沿用404，会话元数据不可读/写返回503。界面保留草稿并显示原因；原运行结果不被错误响应覆盖。

`ConversationPanel` 展示消息、折叠过程与固定底部输入，终态事件后刷新会话。人工审阅或遗留快照恢复后也刷新可继续条件，丢弃最新工作树后及时禁止提交。各轮完整轨迹、配置、上下文、测试和代码在右侧/抽屉检查器查看；Agent回答使用受限Markdown，用户消息、工具结果和补丁按普通文本转义。

## 7. 验证与限制

后端 `tests/test_sessions.py` 与 `tests/web/test_conversations.py` 覆盖完整文件继承、真实 Git 补丁派生、换行转换、独立预算/验收/审阅、跨服务实例读取、重复/冲突/未知请求、并发单槽、HTTP断开及准备时停服、过期和受损快照、历史预算超限。前端会话、页面、Markdown及事件投影测试覆盖实际载荷、三轮原地追加、历史检查与发送目标分离、重试编号、草稿、输入法、防重、忙碌、受限Markdown、复制及丢弃后的可用条件刷新。完整检查命令见 [控制台说明](WEB_CONSOLE.md#6-验证与限制)。

当前仅支持本地单用户、单进程、单任务和线性会话；追加入口为 Web API/页面，CLI 未增加 continue 命令。分层历史压缩与中断接续已接入；运行中插话、并行分支、容器和自动合并仍未交付。旧 Git 记录能核对来源与快照时可兼容继续；旧普通记录缺少来源/文件快照时仍可读取，但要求新建任务。完整 V0.2 尚未完成。


## 8. 会话工作区实现

本次界面重构复用已有HTTP/SSE契约，无后端接口、执行或验收变更。RunDetailPage读取入口运行确定session_id，以 `['conversation', session_id]` 缓存完整会话；工作区React key固定为session_id。各轮仍以 `['run', run_id]` 读取独立快照。POST确认后先缓存真实RunView，再补入已接纳轮次并替换路由，因此连续发送不会重挂载输入和消息视口。

| 前端模块 | 职责 |
| --- | --- |
| pages/RunDetailPage.tsx | 会话身份、最新轮、所选检查轮、取消与响应式布局 |
| components/ConversationPanel.tsx | 消息、底部输入、输入法快捷键及阅读位置 |
| hooks/useConversationSend.ts | 会话草稿、固定父轮/载荷的发送与未知结果确认 |
| components/MarkdownMessage.tsx | 受限Markdown、代码复制及宽表格/代码展示 |
| activity.ts / components/TurnActivity.tsx | 从真实配对事件投影工具/验收过程，历史按需读取 |
| components/RunInspector.tsx | 各轮概况、测试、代码、产物、上下文与完整轨迹 |

最新轮消息过程与检查器共享同一useRunEvents订阅。查看历史只创建只读事件窗口；不订阅旧轮SSE、不重放工具。`inspect`查询参数表示检查对象，`tab`表示详情分类，都不改变追加目标；不属于本会话的inspect值被忽略。输入与未确认载荷只保存在当前标签页，未加入服务端消息编辑、运行中插话或并行分支。

## 9. 与历史压缩的关系

完整原始历史仍从直接父轮核验后继承。启用压缩时复用前轮工作摘要，核对范围、内容指纹及证据正文，再映射到新运行；旧日志和补丁不变。引用只读当前运行或可信祖先，不重放工具。新摘要单独计入本轮预算，已核验摘要复用不额外请求模型；来源不可核对则停止。协议与限制见[上下文管理](CONTEXT_MANAGEMENT.md)。

## 10. 中断后直接发送继续（2026-10-23）

服务退出而没有run_finished时，页面保留“运行已中断”状态。若初始消息、事件连续性和来源目录可核对，普通输入框仍可发送“继续”或新的补充要求；GET、刷新与重启不自动执行。

新运行的HistorySource.interrupted由宿主设置，固定源事件最大序号与重建消息摘要。已落盘工具结果原样继承；尾部已开始但无结果的工具补tool_execution_unknown，尚无开始记录的调用补tool_not_started。这些标记仅进入新运行历史，不能当作旧操作失败或未发生；模型须先核对现场，宿主不重放旧工具。记录损坏或中间批次失配仍拒绝。

代码采用已有逐轮独立副本流程。用户明确提交时，为缺少收尾快照的中断来源捕获一次当前代码，再沿原Git补丁或有界文件副本派生下一轮；不在每个工具批次创建检查点。中断源补丁表示提交继续时的现场，不承诺还原中断瞬间。原run.json与JSONL保留，新一轮重新验收并待审阅。

新消息拥有独立预算和结果，旧用量另保留；未确认的供应商用量保持未知。ConversationView增加可选continuation_notice提示，不作为阻断原因。独立恢复API、执行分支、前端组件和专属测试已删除；旧recovery与resumes路径均返回404。普通会话始终通过followups提交，不存在同轮恢复尝试或跨尝试累计预算。


清理后的RunManifest、RunResult和会话请求不再声明恢复来源、尝试序号或累计预算。为保留普通历史可读性，磁盘读取只移除此前普通运行也会写入的空元数据，并核对普通请求的冗余轮次与线性父关系后丢弃，不改原文件；非空旧恢复来源、非首次序号和未知字段仍拒绝。没有旧检查点加载器、迁移执行器或恢复旁路。
