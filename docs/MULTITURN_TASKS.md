# 多轮任务交互

V0.2 首版已交付，产品范围与 M01—M06 见 [PRD 4.3](PRD.md#43-多轮任务交互的交付范围v02)。本文件维护当前架构、追加规则和接口；实际验证证据集中于 [控制台说明](WEB_CONSOLE.md#7-已保留的验证证据)。历史压缩与中断后普通消息接续已接入；一条用户消息对应一个独立运行，运行中插话和并行分支暂缓。

## 1. 使用流程

1. 从侧栏进入项目会话页。点击“新建对话”提交任务；继续已有工作时，点击该会话进入消息区。首次运行后等待执行、验收及快照收尾。
2. 在会话消息区查看要求和回答，在底部“输入消息”填写下一条要求，点击“发送”或按Enter。
3. 服务核对前轮记录与代码状态，建立新运行，沿用所选目录，显式Git隔离也复用同一会话工作树；原地补入新轮，更新路由但保留同一会话消息区和输入节点。
4. 新轮单独使用预算、调用工具、保存事件；正常完成执行后重新运行宿主登记的验收。代码项目重新等待审阅，可进入“代码改动”查看本轮交付。
5. 运行详情默认收起，点击页头“查看详情”或各轮“本轮详情”回看测试、上下文、产物与补丁；已有详情深链接仍直接展开。检查器可选旧轮，输入仍明确追加到最新轮，查看历史不产生分支。

运行中允许编辑追加输入，但禁止提交；页面说明等待或取消的原因。失败保留输入。刷新、关闭页面或重新启动服务只恢复读取，不自动提交要求或执行旧工具。

## 2. 会话与执行的关系

```text
同一会话（session_id 等于首轮 run_id）
  第1轮 Run A → 第2轮 Run B → 第3轮 Run C
                parent=A      parent=B
```

每条接纳的用户要求对应独立 Run；Run 内部仍可进行多轮模型/工具调用。`turn_index` 从1开始表示用户轮次，`result.model_turns` 表示该次执行的实际模型轮次，两者含义不同。

公开测试自动修复属于同一个Run，repair_attempts为0至2，不新增用户轮次或预算。repair_started中的反馈是宿主测试数据，随历史按原顺序继承。后续用户要求默认继承config.auto_repair，可在“下一轮设置”开启/关闭；网络重试沿用冻结的原载荷，不因下一条选择变化而改写。修复中断后先核对已保存检查与当前代码，重启和查看均不自动恢复。

`RunManifest` 按当前格式保存以下会话字段：

| 字段 | 含义 |
| --- | --- |
| session_id | 网页会话首轮编号；CLI 单轮记录可为空，查询时按自身 run_id 展示 |
| parent_run_id | 直接前轮编号；首轮为空 |
| turn_index | 用户要求的顺序，首轮默认1 |
| origin | 宿主登记的项目/工作区编号与固定路径；普通任务还固定验收器编号 |
| history_source | 后续运行使用的前轮事件最大序号与消息 SHA-256；首轮为空 |

配置默认沿用前轮；每轮文件按本轮开始至结束的实际变化自动登记，不继承前轮产物清单。API 可覆盖已有开放配置，页面沿用本浏览器的公开配置草稿。宿主系统提示重新生成，工作区与验收来源不能通过追加请求任意切换。每轮实际计数从零开始，旧配置和结果保持不变。

## 3. 历史如何继承

`sessions.history_messages` 默认只读取可信终态直接前轮；宿主显式接纳中断来源时，另核对完整事件前缀，为尾部缺失结果补充未知或未开始标记。原日志不改写。前轮初始消息已经包含更早历史，因此不递归重复拼接。保留用户要求、回答、reasoning_content、工具调用及配对结果，去掉旧宿主规则和旧项目指令前缀；配对不完整或记录受损时拒绝继续。

新轮的 `ContextBuilder` 重新加载当前工作区根 AGENTS.md，将当前宿主规则、当前项目指令、继承历史和新要求组成完整输入。历史中的旧目录和旧测试仅作为前轮证据，新轮必须在当前工作区执行并重新验收。模型调用前再次核对前轮事件序号与历史摘要，并记录 `history_loaded`。

完整历史与工具定义继续计入 UTF-8 JSON 输入预算；压缩使用有来源的投影，原始记录保留，不静默截断。超限时本轮 `limit_exceeded`，未实际发出的请求不增加模型/HTTP计数；旧文件、记录与补丁仍保留。预算和计量规则见 [上下文管理](CONTEXT_MANAGEMENT.md)。

## 4. 代码和文件如何继承

### 原目录执行（默认）

会话固定 execution_mode=local、所选路径和目录对象身份，后续消息始终在同一目录执行；允许用户手动编辑当前文件，不从旧补丁或副本恢复。每轮开始/结束单独采集受限差异与产物，供查看旧轮，不作为继续前提；采集失败明确显示，详情不提供保留/丢弃原目录。完整限制见 [本机项目协议](LOCAL_PROJECTS.md#原目录执行与逐轮证据)。

### Git 隔离执行

首次 Git 隔离运行从指定提交建立会话工作树；后续 prepare_turn 只新增本轮证据并复用目录，不创建工作树或应用旧补丁。两轮间手动修改保留，各轮配置、预算、工具轨迹、项目测试、固定产物和相对会话基线的累计补丁分别留存；旧轮证据不重新捕获。

只有最新轮可保留或丢弃共享工作树，旧轮只读，运行中拒绝删除。前轮 kept 不代表新轮已经接受；丢弃后不能继续，但已保存历史文件和补丁仍可下载。不自动提交或合并。新轮尚未启动时准备失败，仅回退会话管理状态，已有目录保持。 每轮 diff 为相对会话初始提交的累计差异；不提供两轮间增量 diff。

## 5. 请求幂等与服务重启

`ConversationService` 在现有 WebRunManager 的全局单槽内准备和启动新轮，执行仍交给唯一 Runner。`SessionStore` 在受保护记录目录 `.sessions/<session_id>.json` 中原子保存线性关系与请求意图；原目录文件证据存放于 `.local-before/<run_id>`、`.local-after/<run_id>` 与 `.local-changes/<run_id>`，Git 证据位于 `.projects/<run_id>/`。这些元数据不成为第二个 JSONL 写入者。

请求以会话内唯一 `request_id` 和完整载荷摘要识别：

| 状态 | 行为 |
| --- | --- |
| preparing | 准备工作区前落盘；同进程重复请求等待同一准备任务 |
| committed | 准备完成后先固定新轮关系，再启动一次 Runner；重复请求返回原运行 |
| failed | 准备失败不推进会话最新轮；同编号重试返回原失败原因 |
| 编号相同但载荷不同 | 返回 request_conflict，不执行新动作 |
| 重启后准备状态不确定或已登记但缺少运行 | 明确说明待核对，不自动再次准备或执行 |

HTTP请求断开不取消后台准备。前端在 sessionStorage 按会话保存当前标签页未发送草稿及未确认请求的原父轮、编号、正文和公开配置；网络失败后用户“重试确认”沿用原载荷。发送期间编辑的不同新草稿继续保留。刷新只恢复输入和确认入口，不自动发送。确定未接纳的校验失败允许用户核对后新提交；未知结果不能通过换编号自动重试。

服务重启后可读完整会话，并从可核对的最新终态明确发起新要求。服务中断后可打开原会话并发送“继续”；新请求继承可核对记录与当前代码，宿主不自动重放旧工具。

## 6. HTTP 与页面契约

`GET /api/runs/{id}/conversation` 返回 `session_id`、`latest_run_id`、有序 `turns`、`can_continue`、可空 `blocked_code/blocked_reason` 和 `busy_run_id`。各轮提供运行关系、用户要求、最终回答、执行/验收状态及可空创建时间。读取不会重新执行或重新捕获代码；GET给出静态可用条件，实际内容核验仍在提交准备时进行。

`POST /api/runs/{id}/followups` 只允许从最新轮追加：

```json
{
  "request_id": "c1f54d17-b15c-4674-aac6-62311d6420f6",
  "prompt": "保留上次修复，再补充参数类型和中文说明。",
  "config": {"limits": {"max_model_turns": 12}}
}
```

`request_id` 为 UUID；`prompt` 为1至65536字符，空白要求被拒绝。`config` 可省略，复用现有受限覆盖字段。不能传入新宿主路径、项目、基线、验收 argv 或凭据。

成功202返回新/原 `RunView`，其中包含会话、前轮和用户轮次。忙碌、旧轮追加、工作区变化、已丢弃和不确定请求返回409及受控原因；请求结构错误沿用422，运行不存在沿用404，会话元数据不可读/写返回503。界面保留草稿并显示原因；原运行结果不被错误响应覆盖。

`ConversationPanel` 展示消息、折叠过程与固定底部输入，终态事件后刷新会话。人工审阅或遗留快照恢复后也刷新可继续条件，丢弃最新工作树后及时禁止提交。各轮完整轨迹、配置、上下文、测试和代码在右侧/抽屉检查器查看；Agent回答使用受限Markdown，用户消息、工具结果和补丁按普通文本转义。

## 7. 验证与限制

后端 `tests/test_sessions.py` 与 `tests/web/test_conversations.py` 覆盖原目录复用、Git 会话工作树复用、换行转换、独立预算/验收/审阅、跨服务实例读取、重复/冲突/未知请求、并发单槽、HTTP断开及准备时停服、受损历史产物、历史预算超限。前端会话、页面、Markdown及事件投影测试覆盖实际载荷、三轮原地追加、历史检查与发送目标分离、重试编号、草稿、输入法、防重、忙碌、受限Markdown、复制及丢弃后的可用条件刷新。完整检查命令见 [控制台说明](WEB_CONSOLE.md#6-验证与限制)。

当前仅支持本地单用户、单进程、单任务和线性会话；追加入口为 Web API/页面，CLI 未增加 continue 命令。分层历史压缩与中断接续已接入；运行中插话、并行分支、容器和自动合并仍未交付。仅接纳能按当前格式核对记录与来源的会话；不清洗旧协议字段或迁移旧草稿。完整 V0.2 尚未完成。


## 8. 会话工作区实现

本次界面重构复用已有HTTP/SSE契约，无后端接口、执行或验收变更。RunDetailPage读取入口运行确定session_id，以 `['conversation', session_id]` 缓存完整会话；工作区React key固定为session_id。各轮仍以 `['run', run_id]` 读取独立快照。POST确认后先缓存真实RunView，再补入已接纳轮次并替换路由，因此连续发送不会重挂载输入和消息视口。

| 前端模块 | 职责 |
| --- | --- |
| pages/RunDetailPage.tsx | 会话身份、最新轮、所选检查轮、取消与响应式布局 |
| components/ConversationPanel.tsx | 消息、底部输入、输入法快捷键及阅读位置 |
| hooks/useConversationSend.ts | 会话草稿、固定父轮/载荷的发送与未知结果确认 |
| components/MarkdownMessage.tsx | 受限Markdown、代码复制及宽表格/代码展示 |
| activity.ts / components/TurnActivity.tsx | 从真实配对事件投影工具/验收过程，历史按需读取 |
| components/RunInspector.tsx | 各轮结果、文件与诊断：测试结果单独阅读，差异与产物共用文件分类，上下文与轨迹归入诊断 |

最新轮消息过程与检查器共享同一useRunEvents订阅。查看历史只创建只读事件窗口；不订阅旧轮SSE、不重放工具。`inspect`查询参数表示检查对象，`tab`表示详情分类，都不改变追加目标；不属于本会话的inspect值被忽略。输入与未确认载荷只保存在当前标签页，未加入服务端消息编辑、运行中插话或并行分支。

## 9. 与历史压缩的关系

完整原始历史仍从直接父轮核验后继承。启用压缩时复用前轮工作摘要，核对范围、内容指纹及证据正文，再映射到新运行；旧日志和补丁不变。引用只读当前运行或可信祖先，不重放工具。新摘要单独计入本轮预算，已核验摘要复用不额外请求模型；来源不可核对则停止。协议与限制见[上下文管理](CONTEXT_MANAGEMENT.md)。

## 10. 中断后直接发送继续（2026-10-23）

服务退出而没有run_finished时，页面保留“运行已中断”状态。若初始消息、事件连续性和来源目录可核对，普通输入框仍可发送“继续”或新的补充要求；GET、刷新与重启不自动执行。

新运行的HistorySource.interrupted由宿主设置，固定源事件最大序号与重建消息摘要。已落盘工具结果原样继承；尾部已开始但无结果的工具补tool_execution_unknown，尚无开始记录的调用补tool_not_started。这些标记仅进入新运行历史，不能当作旧操作失败或未发生；模型须先核对现场，宿主不重放旧工具。记录损坏或中间批次失配仍拒绝。

原目录会话继续使用身份已核对的当前目录。明确创建的 Git 工作树在中断接续时捕获当前代码，并复用同一会话目录；不在每个工具批次创建检查点。中断源补丁表示提交继续时的现场，不承诺还原中断瞬间。原run.json与JSONL保留，新一轮重新验收；仅隔离Git工作树等待保留/丢弃。

新消息拥有独立预算和结果，旧用量另保留；未确认的供应商用量保持未知。ConversationView增加可选continuation_notice提示，不作为阻断原因。独立恢复API、执行分支、前端组件和专属测试已删除；旧recovery与resumes路径均返回404。普通会话始终通过followups提交，不存在同轮恢复尝试或跨尝试累计预算。


RunManifest、RunResult 和会话请求只按当前数据模型严格读取，不再声明恢复来源、尝试序号或累计预算。已删除旧空元数据清洗、冗余轮次删除及缺失 conversation_start 的推断；字段未知或必要历史信息缺失时明确拒绝，不改原文件。没有旧检查点加载器、迁移执行器或恢复旁路。


## 11. 项目与会话导航（2026-10-24）

界面以“项目 → 会话 → 多轮消息”组织。侧栏项目名称进入项目会话页，可展开最近五个会话；项目页展示完整分页列表，并提供明确的新建对话入口。首页最近会话与“全部会话”同样每会话一条，使用第一条要求作为标题，显示已接纳轮数、最后活动时间与最新轮状态。点击正常会话默认进入最新轮；旧 `/runs/{run_id}` 深链接仍展示完整会话并可检查该轮。

新建对话从项目页进入时固定该来源，优先于浏览器上次选中的目录；不同项目的新会话文字草稿分别保存在当前标签页。已有会话的未发送消息仍按稳定 session_id 保存，切换到项目、全部会话或其他对话再返回后恢复。手机用“打开项目与会话导航”按钮进入同一项目树。

新增只读 `GET /api/conversations`：offset从0开始，limit为1..100（默认20），project_id可选，status按最新轮 execution_status 筛选。服务先依据 run.json 与 `.sessions` 的线性关系核对并聚合完整会话，再筛选、排序、分页；不对某一页运行做去重。返回 items/total/busy_run_id；运行级列表接口已删除，单轮事实通过 `/api/runs/{id}` 获取。

每个摘要含 session_id、title、entry_run_id、latest_run_id、turn_count、created_at、updated_at、source、latest、error。source固定原登记编号、类型和路径，只有三者仍匹配当前登记才属于当前项目；相同编号改指新路径时，旧会话只保留在全部会话。latest仅含最新轮执行、验收、清理与活动阶段，不附带完整回答和上下文。

正常 entry_run_id 指向最新已接纳轮次。最新记录缺失、元数据损坏或轮次关联不符时，保留可读入口并标记“记录待核对”，不退回旧轮伪装成功；无法核对的轮数和最新状态为空。会话详情另外返回可空source，支持返回所属项目。列表无文件写入、不更新最近打开时间、不调用模型或重新执行工具；更新来源、刷新列表与服务重启均不会创建运行。

联动验收覆盖：三轮只有一条导航、项目隔离、聚合后分页、最新状态筛选、跨页草稿、旧深链接、手机抽屉和重启后继续。具体结果统一见 WEB_CONSOLE.md 的验证记录。
