# 工作台界面与实时对话

统一项目导航、聊天、任务、计划、子 Agent、文件、结果、诊断、后台工作与设置的布局和样式。视觉采用中性表面、单一强调色、紧凑列表和细分隔；侧栏底部的三段图标按钮直接切换浅色、深色与跟随系统，偏好只保存在当前浏览器，不改变运行配置。

## 信息结构

- 左侧按项目组织会话，保留全部会话、后台工作与设置入口。
- 中央以对话为主：用户消息、实时过程与最终回答。运行中的过程默认展开，结束后折叠；模型文字和工具按实际顺序呈现，参数与原始结果按需展开。
- 工作栏提供任务进度、计划和子 Agent 入口。右侧工作面板分别展示任务、计划、Agent、结果、文件和诊断；窄屏改用抽屉，切换面板不重建输入节点。
- 任务采用紧凑列表，详情包含范围、完成条件、依赖与真实证据。人工修改沿用版本校验，归档和历史隐藏写入入口。
- 项目会话分类直接使用文字标签切换，执行状态收进筛选菜单；仅显式进入多选后显示行复选框及批量操作，退出清空选择。
- 子 Agent 列表展示角色、任务和真实状态；详情承载报告、来源、分页原文及轨迹。停止单个子项仍由独立接口处理。
- 自动与先规划共用同一模式组件，切换只影响下一次提交。计划批准、修改和拒绝仍绑定当前请求及版本。
- 执行时输入区的发送按钮切换为停止，用户可继续编辑草稿。正常忙碌不重复显示为阻塞警告；未知发送和真正错误仍明确展示。

## 流式数据链路

`DeepSeek SSE → StreamAssembler → RunContext.model_delta → events.jsonl → 运行 SSE → useRunEvents.timeline → TurnActivity`

模型请求统一使用流协议。首片立即发布，后续同通道文本按约 80ms 或累计 2KiB 合并，通道切换和结束时排空。`model_delta` 包含 `model_turn`、`channel`、`delta`；工具参数另含 `tool_index`、`call_id`、`name`。生成中的参数只供展示，完整响应及调用配对校验通过后才执行工具。

完整 `assistant_message` 覆盖同轮增量。宿主检查、可能的自动修复与收尾结束后，最终回答才固定展示；检查失败及后续修复过程均保留。内部历史压缩请求不进入用户文字流，供应商实际返回的推理内容独立折叠。

原始诊断事件仍使用默认 400 条、最多 1000 条的窗口；对话另将文字累计成内容块，最多保留 1200 个块。长答复不会因原始增量被裁剪而丢失开头。历史展开按页补齐，内容块按最后事件序号去重；同轮终态刷新保留已有内容，断线不重放工具。未完成输出保留为前缀，不当作最终答复；已有输出后不透明重试模型请求。

## 验收

自动检查覆盖首字时机、跨网络包中文、交错工具参数、断流不重试、事件先于工具执行、长输出跨窗口、重复补读、终态折叠、任务版本操作、子报告分页及连续会话。前端执行类型检查、行为回归与生产构建，后端执行离线回归。

2026-11-01 验证记录：前端 35 个文件、171 项测试全部通过，类型检查、生产构建和差异格式检查通过。前端测试默认串行，避免 Windows 下 Ant Design/JSDOM 并行布局计算造成时限误报。

后端首轮全量为 809 项通过、10 项失败、11 项平台跳过。9 项目录归属失败来自临时目录位于本 Git 仓库内，另 1 项为清理时序；包含全部失败项的 29 项测试改到仓库外 D 盘专属目录复核后全部通过，合计覆盖 819 项通过和 11 项平台跳过。首轮及复核日志保存在 `.runtime/ui-redesign/`，未把首轮结果描述为一次全绿。

真实 HTTP 验收完成计划批准、后续执行、子 Agent 报告和终态读取；收到 29 条模型文字增量，增量先于完整消息，最终 `run_finished` 正常结束。此项使用离线模型和真实宿主运行，不代表已验证供应商线上服务。

浏览器自动视觉验收因工具无法可靠识别 Windows 窗口网址而停止，未将桌面/窄屏截图检查标记为通过。可使用离线服务人工复核，所有数据写入专属目录：

夹具使用真实任务、计划、子运行与文件工具，模型响应由脚本提供，不访问供应商或修改用户项目。服务仅监听本机；新建、自动执行、待批准计划、任务及 Agent 详情均可操作。
